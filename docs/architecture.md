# 架构与时序边界

## 五级分工

| 阶段 | 内容 | 跨边界规则 |
|---|---|---|
| IF | 64 项 BTB/方向预测、寄存命令、在途响应归属、8 项指令 FIFO 和队首缓存 | 请求与 ID 输出均寄存；空间信用只看寄存状态 |
| ID | 完整合法性译码、2R1W 寄存器读取、生产者标签选择 | 操作数与标签进入 2 项 ID/EX 队列 |
| EX | 注册结果转发、ALU、地址计算、分支；启动流水乘法或等待迭代除法 | 结果/访存事务及乘法令牌进入 4 项 EX/MEM 队列 |
| MEM | 已寄存事务发起、一次接受、响应归属、错误/字节处理；队首等乘法结果 | 结果只进入独立 WB 数据寄存器 |
| WB | 按程序顺序写 RF/CSR，退休，精确异常 | 不把原始 RAM 返回直接送入 EX |

这些是五个逻辑阶段；队列容量和多周期单元不能解释成每条指令固定五拍。
ID 同时预译码 19 位 EX 控制，随队列寄存；EX 采用并行的一位结果使能选择。
无停顿时 ALU 每拍可通过一级；load/store 和乘除法驻留时间依赖对应单元。

取指 FIFO 的可见队首用寄存器缓存指令、PC/故障和预测元数据，ID 不再从异步队列读取串到依赖选择。
队列消费时读取下一项补充；空队列插入和单项同拍出入队在同一时钟沿直接捕获响应。
总容量仍为八项，没有增加固定等待拍。下一项读取地址仅依赖寄存指针，不由 ID ready 选择。

## 为什么不会重现旧的跨模块长链

旧的“转发 → AGU → 合法性 → 双访存仲裁 → RAM”被 EX/MEM 队列寄存器切断。
RAM 请求只能从已寄存的 EX/MEM 队首发出；MEM 在请求被接受时保存响应归属，
不再提前复制事务再等一拍发请求。IF 和 LSU 使用双口 RAM 的固定 A/B 端口，
不建立通用主设备交叉仲裁矩阵，仅对同字读写碰撞暂停取指。

`nc_fifo.in_ready` 仅依赖本地寄存的 count；队列满时不做 pop→ready 组合直通。
MEM 的外部响应可以影响 MEM/WB 捕获，但不会穿过队列反向影响 ID 发射。
WB 故障位本身已寄存，只对年轻请求作短距离取消。不存在地址加法结果当拍驱动全局 flush 的路径。

分支在 EX 确定结果；只有实际下一 PC 与随指令保存的预测不符才恢复，
修正 PC 先进入 redirect 寄存器，下一拍清 IF/ID/EX 的年轻项。
同拍进入队列的年轻指令也会被清除，不能越过分支执行。相较直接组合冲刷，
这付出一拍恢复控制延迟，但避免分支比较串到整个前端的宽寄存器使能。
预测正确的分支/跳转继续执行，不等到 WB 再确认。
重定向资格与目标数据并行计算，直接跳转的非顺序判断使用立即数是否为 4，
JALR 保留实际目标比较。目标数据每拍预写，窄有效位资格化其生效，避免宽目标寄存器的迟到 CE。
误预测比较在目标/顺序两侧并行完成，分支条件只选择比较结果；
修正令牌同样每拍预写，由已寄存的 branch_redirect 决定下一拍是否使用。
分支/跳转的异常地址候选值提前资格化，taken 只在已准备好的候选向量之间选择；
异常有效位和原因独立产生，保留非法指令、取指故障覆盖其他异常的优先级。
取指在接收到这个已寄存的重定向命令时，若无必须保持的旧请求，直接装入目标请求寄存器；
不再先更新顺序 PC、下一拍才生成请求。已发布而未接受的旧请求仍保持地址和 valid，
被标记为过期并排空，不能覆盖成新目标。

仍然存在正常的单级组合逻辑，例如“寄存转发值 → ALU/AGU → EX/MEM”。
不能声称所有长路径都消失；最终应以 STA 端点和裕量验证。
最新时序和资源见 [EX/ID 单级路径实验](ex_id_finish.md)，当前仍是单发射。
已采纳的周期优化见 [IPC 优化记录](ipc_opt.md)。
双发结构评估见已采纳版的 [时序收尾记录](timing_pair.md)。
[单级与周转优化](stage_opt.md)、[乘法流水记录](mul_pipeline.md) 保留为历史基线。
已采纳的 BTB 基线见 [BTB 记录](btb64.md)。

## BTB 与取指 FIFO

64 项直接映射 BTB，索引为 PC[7:2]，完整 tag 为 PC[31:8]。
每项保存 30 位字对齐目标、条件分支标志、1 位已解析局部历史和两组 2 位饱和计数器；
64 个 valid 位复位/失效。命中的条件分支按最近已解析的方向选择计数器，用其高位预测；
无条件跳转命中时预测跳转。首次分配将两个计数器均初始化为本次方向的弱状态，
后续训练旧历史对应的计数器，再将本次实际方向写入历史位。
历史只在已寄存训练到达 IF 时更新，不做推测更新，也不增加跨级历史恢复控制。

BTB 查询只从 IF 寄存 PC 到下一 PC 寄存器，请求地址始终由 cmd_pc 寄存器驱动。
每条指令的 32 位预测信息（hit、taken、目标字地址）经命令、在途响应、八项 FIFO、
队首缓存和 ID/EX 两槽保存，不能在出队时重新查询可变的预测表。
纠正命令直接装入请求寄存器，此命令按顺序预测，避免 EX 纠正目标再串行查 BTB。

EX 接受的非异常分支经训练寄存器更新表项，未等到退休；
更老异常可能留下预测状态，但预测状态不是架构状态，后续仍逐条核对并纠正。
命中的过期非分支项被失效；FENCE/FENCE.I 退休经寄存命令清 valid。
原有背压请求保持、过期请求标记与响应排空机制继续使用。

## 相关、转发与异常

8 个循环令牌记录在途指令的目的寄存器，ID 从中选择最新生产者。
实现使用固定槽位比较和 tail 两侧的优先选择，避免旋转索引访问目的寄存器数组。
两侧的生产者编码并行完成，最终选择 3 位 tag，避免先选宽候选掩码再串编码。
令牌不是乱序调度/完成队列：EX 只执行头部，MEM/WB 始终顺序。
它允许 WAW，不因重复写同一寄存器而停发；消费者仍绑定正确的最新生产者。

EX 和乘法结果转发经过独立寄存，load 从 WB 寄存值转发。两个 ID/EX 项都会记住转发结果，
每项局部匹配广播后再选择队首；入槽同拍捕获保留生产者编码 tag 与广播 tag 的比较。
避免背压时生产者离开流水级后操作数丢失。未就绪的 load-use 消费者在 EX 等待，
更年轻指令不能越过它。x0 不建立依赖、不允许写入。

普通 load/store 不排空流水线。EX/MEM 队列允许缓冲后续独立结果；
单个数据事务在 MEM 中等待响应。store 只能按顺序在 MEM 发起，
更老 WB 异常先取消年轻事务，已发布且未接受的请求保持稳定。
分支和访存异常的错误路径不会产生寄存器退休或设备写入。

四项 EX/MEM 载荷压缩为 184 位，结果/store 数据共用一个字，地址/CSR 新值/异常值共用另一个字。
MEM 仍按相同完整接口展开，未将新的宽选择串到 EX 之后再去 RAM。
EX 直接按已寄存指令类别生成辅助字段，不再先把对齐判断扩展为宽异常值再压缩。
干净的分支/跳转保存实际 next-PC，访存保存地址，CSR 保存新值；fetch fault/illegal 分别优先保存 PC/指令。
无异常分支的辅助字段会携带未使用的 next-PC；MEM 仅在异常有效时将其解释为 tval，正常分支不写 mtval。
EBREAK 保存 PC，ECALL 等其余非访存异常值为零。原完整 EX 输出和故障优先级保持一致。
成功响应可以与下一访存请求同拍周转，仍最多一个尚未返回的事务；旧上下文进入 WB，新上下文进入 held。
响应的错误标志先禁止下一请求，WB 下一拍精确取消年轻项，不提前产生年轻设备写。
响应数据经过 lane 选择/符号扩展后只进入 WB，不能直接作为 EX 转发源。
byte/half/word、lane 和符号控制在请求接受沿预译码并寄存，与 held 上下文同时更新；
返回数据经过并行选择和符号扩展到 WB，没有增加 load 数据流水级。
旧响应与新请求同拍周转时，旧格式控制供旧 WB 捕获，新控制随后用于新事务。

响应同拍还可接受一条非访存指令：旧响应进入 WB，新指令复用 held 暂存。
下一拍 held 的普通结果进入 WB，同时可接受后面的访存请求，或暂存再下一条普通指令。
仍然每拍最多一个 WB、一个尚未返回的数据事务，不提前退休，不增加 load 返回级。
MEM 的 BUFFERED 状态若保存异常，先禁止所有年轻接受与请求，下一拍由 WB 发出 kill。
旧响应错误同样禁止年轻接受；乘法只在接受时查询并消费结果，暂存的是完成值。
所有新增控制终止于 MEM 本地寄存器或 EX/MEM 出队端，队列入队信用仍只依赖寄存 count。

CSR/FENCE、ECALL/EBREAK/MRET/WFI 以及 ID 已发现的异常使用序列化控制。
精确异常在 WB 写 mepc/mcause/mtval 并清年轻指令，异常指令不计入 minstret。
不对普通 ALU、分支、load/store 使用全流水线串行化。

## 当前真实的性能取舍

- 单发射，64 项直接映射 BTB，每项 1 位已解析局部历史和两组 2 位方向计数器；没有全局历史或返回地址栈。
- 数据接口最多一个已接受事务，未实现非阻塞 LSU 或 store buffer。
- 乘法使用 4 个紫光 APM 的有寄存部分积，单元每拍可接收一条，后续独立 EX 可以重叠执行。
  接收沿为 E0，普通 MUL 在 E2 寄存结果，MULH/MULHSU/MULHU 在 E3 寄存结果。
  八项令牌结果暂存保留已完成值，MEM 只消费队首，全部仍经 WB 顺序退休。
  高/低位同拍完成时两者均保存；单广播端口优先低位，高位可经有序 MEM/WB 转发。
  有限队列、相关和在途信用仍限制整核吞吐；除法/余数保持 32 步阻塞迭代。
- load-use 等到 WB 注册结果，不以 RAW RAM 数据直接前递来缩短等待。
- 队列满时恢复接收会有局部信用延迟，避免组合 ready 级联。
- 中断停止新发射、排空已发射指令；总线若永不响应，IRQ 也无法保证有界延迟。
  外部集成必须保证接受的事务最终响应，或由适配器返回超时错误。

## 指令与 CSR 范围

RV32I、M、Zicsr 和 FENCE.I；不包含 C/A/F/D、U/S 模式、PMP/MMU、调试规范。
WFI 作为合法提示指令执行，不实施时钟门控。未对齐访问产生异常，不拆分访问。

CSR 包含 mstatus、misa、mie、mtvec、mscratch、mepc、mcause、mtval、mip，
mcycle/minstret 及高字、只读 cycle/instret 及高字、机器标识。
不支持的 CSR 或对只读 CSR 的写操作产生非法指令异常。
mstatus 仅 MIE/MPIE 可变，MPP 固定 M；mtvec 仅支持 direct/vectored。
外部、软件、定时器中断分别使用 cause 11/3/7、mie 位 11/3/7，优先级为外部→软件→定时器。
核心 IRQ 输入要求已同步到 clk；当前板级只使用本地同步定时器。

## IP 实际使用

PLL 与两块真双口 DRM 通过独立生成的紫光 IP 实例化。
取指 FIFO 的指令字使用 32 个 LUT RAM；PC/故障与预测元数据使用触发器，
避免寄存 PC 到 LUT RAM 写数据端的零级逻辑 hold 短路径，功能和周期不变。
寄存器堆无数组复位，2 个读端口由综合器映射为两份 32×32 分布式 RAM。
BTB 的 tag/目标/方向信息映射为紫光 GTP_RAM32X1DP/SP，具体数量见当前 IP 映射报告。
四项 EX/MEM 队列被综合为分布式 RAM；当前已通过载荷复用减小宽度，
强制全 FF 的候选因频率下降和 hold 裕量较小未保留；
乘法结果暂存指定为 FF，未引入异步最终求和到 EX 的旁路。
乘法使用 `syn_dspstyle="block_mult"`，寄存输入/部分积；需看 APM 映射报告，不能只凭属性声称用了硬件 DSP。
功能仿真使用明确的同步 RAM 模型；模型与生产 IP 分开，不能同时编译。
