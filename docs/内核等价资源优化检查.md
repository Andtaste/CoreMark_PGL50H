## 2. 第一批候选：保持周期和接口

### 2.1 ALU 加减法表达式

位置：[exu_alu_datapath.v](https://github.com/Andtaste/CoreMark_PGL50H/blob/b9e184f/hardware/pds/source/core/exu_alu_datapath.v)，约 104 行。
当前为 `a + (sub ? -b : b)`。建议对照 `a + (b ^ {32{sub}}) + sub` 的综合结果，
显式表达单个加减法器的条件反相与进位，避免形成独立取负后再加法的路径。
两种写法按 32 位截断的结果一致；PDS 可能已经识别原模式，因此不预估省多少 LUT。

### 2.2 一个移位器支持 SLL/SRL/SRA

同文件约 106–111 行：当前左移、右移分别表达，SRA 额外计算全一移位掩码再填符号。
先用 33 位显式符号扩展和 `>>>` 合并 SRL/SRA：SRL 扩展位为 0，SRA 为操作数符号位。
进一步用“输入位序翻转 → 统一右移 → 输出位序翻转”实现 SLL。
翻转是连线，选择方向需要输入/输出复用器；净收益需综合确认，不能把整个左移器
的资源都当成净节省。保留结果选择优先级，不能假定任意多热控制输入均合法。

参考：[Ibex ALU](https://github.com/lowRISC/ibex/blob/master/rtl/ibex_alu.sv)，
实际采用位序翻转和统一右移结构。

### 2.3 有符号/无符号比较共享

同文件约 114–129 行：当前分别表达 signed >= 和 unsigned >=。
可先算无符号 `lt_u = a < b`，再生成
`lt_s = (a[31] ^ b[31]) ? a[31] : lt_u`，供 SLT/SLTU 和分支共同使用。
这保留比较结果，不增加执行周期；比较器是否已被 PDS 合并需看新网表。

不要进一步把分支比较和分支目标计算全部压到同一个加法器：
当前分支在同一执行周期同时比较 rs1/rs2 与计算 PC+offset，强行共享会改变周期。

### 2.4 访存：先选窄数据，再符号扩展

位置：[exu_mem.v](https://github.com/Andtaste/CoreMark_PGL50H/blob/b9e184f/hardware/pds/source/core/exu_mem.v)，约 82–108 行。
当前 LB 的四个候选先各自扩展成 32 位再选择；可先按地址选择 8 位，再扩展一次。
LH 同理先选 16 位，再扩展一次。保持奇地址半字的原输出、未对齐标志和操作优先级。
SB/SH 可研究按字节 lane 直接生成结果，避免多份 32 位中间结果再复用。
只重构数据组合逻辑，保持 mem_rsp_hsked_r、store 写使能和 stall 的原时序。

LH 当前拼接用了 24 个符号位+16 位数据，赋值后被截成 32 位。
改成 16 个符号位可以消除宽度问题，但单独改这处通常不会省硬件。

### 2.5 除法器：比较与减法共用一次宽减法

位置：[divider.v](../hardware/pds/source/core/divider.v)，约 60–63 行。
当前 `minuend >= divisor_r` 与 `minuend - divisor_r` 分别表达。
可用 33 位无符号差 `d = {1'b0,minuend} - {1'b0,divisor_r}`：
`!d[32]` 判断 >=，`d[31:0]` 提供差。需保留除零、符号取反、溢出和 abort 行为。

计数器原来是 32 位单热右移，bit31 恒为 0 可能已优化。
可用 5 位计数器从 31 数到 0，在 0 的那次 CALC 进入 END，以保持原 32 次 CALC。
这有望省约 26 个计数 FF，但减法/译码逻辑会增加，不能保证 LUT 也减少。
单热状态机改二进制同样是 FF 与译码/时序的交换，不作为第一优先。

### 2.6 RIB：分离目标选择和授权屏蔽

位置：[rib.v](https://github.com/Andtaste/CoreMark_PGL50H/blob/b9e184f/hardware/pds/source/sys_bus/rib.v)，约 229–245 行。
当前每个主设备返回数据为五项 `grant & slave_data` 的按位或。
可对照“按地址目标选择从设备数据，再用任意 grant 屏蔽”的结构。
grant 仍按现有逐从设备仲裁生成，保持未授权/非法目标输出为零与所有优先级。
由于相同主设备最多命中一个目标，定义值输入下这是可等价重构的复用结构；
现有 OR 树也可能更适合 LUT，必须以报告决定。

保留现有全连接功能时，不宜直接把所有外设并成单个仲裁出口：
那会取消两个主设备访问不同外设时的并行行为。
IF 仅连 ram1、禁止 IF 从 ram2/外设取指，也属于功能裁剪而非完全等价。
现有 m0 写数据/写使能常量和各从设备未用地址高位，综合本就可能自动裁剪。

## 3. 节省潜力较大、实现约束较多

### 3.1 GPR 使用分布式 RAM

位置：[gpr_reg.v](../hardware/pds/source/core/gpr_reg.v)，约 39–56 行。
当前 x1–x31 用 992 个无复位 FF，同步写、两个异步读端口，且有同周期写回旁路。
建议两个相同 RAM 副本同时写，每个副本提供一个异步读端口；x0 仍强制为零，
输出仍保留 `(we && waddr==raddr) ? wdata : ram[raddr]`。

本地 PDS 库含 GTP_RAM16X4DP 等分布式 RAM 原语，支持同步写/异步读。
它提供 16 深度与一个读端口，需要组成 32 深度/32 位及两份读副本。
是否成功推断到当前 Logos 器件、使用多少 LUTRAM/额外复用器，需实际映射确认。
预计能替代大量 GPR FF，但不会省掉其余流水线寄存器，不能照搬其他 FPGA 的数字。
原 GPR 复位不清空：不能为了 RAM 推断而新增整个寄存器组清零或删除写回旁路。
RAM 初始化定义与原未初始化状态的差异，也应按架构允许的上电行为明确处理。

参考：[Ibex FPGA register file](https://ibex-core.readthedocs.io/en/stable/03_reference/register_file.html)。
其采用同步写/异步读 RAM；但 Ibex 的接口没有我们的写回旁路，因此不能直接替换。
同步读 DRM 会增加读延迟，需要改流水线，不属于这一项的等价替代。

### 3.2 乘法器的有符号处理

位置：[exu_muldiv.v](../hardware/pds/source/core/exu_muldiv.v)，约 74–95 行。
当前先对两个操作数取绝对值，再无符号 32×32 乘法，随后有条件对 64 位乘积取负。
可研究直接有符号扩展乘法，或无符号乘积的高半字符号修正：
`high_signed = high_unsigned - (signed_a && a[31] ? b : 0)
                              - (signed_b && b[31] ? a : 0)`（模 2^32）。
这样避免整段 64 位取负；但会引入高半字减法，扩大乘法宽度还可能增加 APM。
保持现有两周期乘法握手，比较总 LUT/APM/Setup；不能承诺净节省。
逐位串行乘法省 APM 但增加周期，属于另一种架构取舍。

### 3.3 CSR 与统计计数器

位置：[csr_reg.v](../hardware/pds/source/core/csr_reg.v)。七个 32 位统计计数器
本身为 224 位存储，还要求同周期可同时累加、饱和和 sticky overflow。
保持这些行为时不能拿单个加法器轮流计数，也不能缩短计数宽度。
可以对照将饱和判断前置到更新使能的写法，并检查读复用/写译码是否重复。
同时必须保留写 control 时该周期暂停事件更新、清零和 enable 的原优先级。
这可能被综合工具自动完成，不能把 CSR 的 789 LUT 都算成可省。

六个通用 CSR 当前允许 32 位写入并读回，即使某些位不参与执行，也不能直接删掉。
cycle 的 64 位自然计数器可保持常规写法，强行分段计数未必省 LUT，且易改进位边界。

## 4. 已有自动优化与其余检查

- idu_exu 的 inst_o 只供内部观察/TB 使用；实际 PDS 报告中对应的执行级 inst_ff
  已被删除。删源码不能再省 32 FF。TB 当前 CoreMark 结束判断仍引用此信号。
- CLINT 的 cause 大部分位恒定、32 位 CSR 地址的常零位、未使用 wire/输出，
  综合已能传播常量或删除；按源码声明宽度计算节省会高估。
- IDU/dispatch/commit 多处 case(1'b1) 是带优先级的选择。
  一次改成掩码 OR 会改变多热情况下的输出，需要证明合法控制互斥；不能机械改。
- ALU/访存操作数在 dispatch 已做屏蔽，数据通路又按 req 屏蔽。
  可跨模块合并选择以缩短路径，但工具可能已吸收重复逻辑，且要保留非活动输出行为。
- IF/ID、ID/EX 数据复位/冲刷归零可用 valid 位与出口屏蔽替代一部分 payload 清零。
  这是组合掩码和复位网络的交换，必须确保 bubble 的异常、中断、CSR、访存及统计
  均被屏蔽；不是直接删除复位即可等价。PC 回退、pc_prev 与握手历史不能直接删除。
- pipe_ctrl、rst_ctrl 较小；复位同步器应按可靠性需求保留，不通过减级省资源。
- 关闭 JTAG、移除 profiling、减少 SRAM 容量、改 RV32E、删除 M 扩展都能减少资源，
  但改变功能或配置，不列为等价优化。
- simulation/models/memory/pds_ram_models.v 是仿真行为模型，不在 PDS 硬件综合输入中；
  重写它不会减少板上资源。板上 48 DRM 由实际 RAM IP 决定。

## 5. 时序与建议顺序

已有最差 Setup 路径为 ID/EX info_bus_ff 的控制位到 ram2 的写数据端，
经过执行数据选择、总线及 RAM 接口，裕量 +1.317 ns。
它支持优先检查数据复用结构，但不证明每个省面积重构都会改善时序。

建议第一批：ALU 加减法/SRL-SRA/比较共享 → 访存窄选择 → 除法比较/减法共享。
第二批：GPR 分布式 RAM → 全方向共享移位器 → RIB 返回复用结构。
第三批：乘法符号修正、CSR 更新与跨模块选择合并。
每项单独比较全 SoC 的 LUT/FF/LUTRAM/DRM/APM 与多角 Setup/Hold；
保持相同器件、约束和软件，用功能等价/定向验证确认后再合并。
以上是后续实施的验证建议，本次未执行。
