# 可重叠流水乘法重构

本页保留乘法重构时的基线数据；后续单级逻辑与等待优化见 [最新报告](stage_opt.md)。

本轮以用户明确采纳的 BTB64 版本为基线，基线归档在 `mul_pipeline/before/`。
`accepted_baseline.json` 仍保留 BTB64 的采纳状态，本轮乘法实现另行记录。
软件镜像、BTB、取指 FIFO8、PLL、RAM IP 和约束没有修改，也没有引入 EX 提前访存。

最终设备报告统计总数为 529（相对原版净增 269）。不能把 RAM 原语数量当作实际有效存储位数。
较浅队列原先使用 FF，扩容后映射为 LUT RAM，因此总 FF 反而下降。

## 最终时序与取舍

四组 slow/fast setup/hold 均无违例。最差 setup 从取指队首的 `head_inst[22]`
到 ID 操作数槽的 `vb[1][22]`，经过源寄存器比较、最新生产者选择、tag 匹配和入槽数据选择。
共 10 级逻辑，逻辑 4.162 ns、布线 7.326 ns；源 `rs2[2]` 扇出 217，
末端局部选择网络扇出 39。当前主要瓶颈是 ID 依赖/捕获路径，路径在 ID/EX 操作数寄存器终止。
它没有继续串过乘法、ALU/AGU、访存或前端重定向；现有单级组合路径仍需后续优化。

最差 hold 是已寄存 BTB 训练地址到 tag RAM 的短路径，slow +0.151 ns、fast +0.119 ns。
本轮保留原 tag 比较方式，没有重新采用用户已放弃的入槽掩码方案。

实验中还试过并行掩码 OR 选择，频率收益不足且增加 LUT，并出现 BTB 短路径 hold 违例，已撤回。
提前完成低位 MUL 的中间候选曾得到 85.339 MHz，但修正空队列 readiness 后重新完整布局的最终值是
83.879 MHz；本报告所有最终指标均使用最后一次实现，不混用中间候选的频率。
各候选保存在 `mul_pipeline/candidates/`。

## 实现与时序边界

删除阻塞乘法状态机，保留独立的阻塞式 `nc_divide`，乘法改为 `nc_mul_pipeline`：

1. EX 接受乘法时，将操作数、MUL 类型和令牌写入输入寄存器。
2. 四个 17×17 部分积由紫光 APM 实现，部分积跨寄存边界。
3. 分段求和得到低位 MUL，直接进入结果/广播寄存器；不再等待高位加法。
4. MULH/MULHSU/MULHU 再经过高位求和，进入同样的结果/广播寄存器。

接收沿记为 E0，低位结果在 E2 寄存，高位结果在 E3 寄存。
单元允许每拍接收一个输入；低位与高位同拍完成时，两个结果分别写入不同令牌的暂存项。
单个乘法广播端口优先低位，冲突的高位结果保留在暂存项，可由有序 MEM/WB 提供给消费者。
没有丢弃结果，也没有让独立乘法单元直接写 RF。

EX/MEM 有序队列从两项扩为四项，允许后续独立指令在较老乘法计算期间执行。
输入信用仍只依赖寄存的占用计数，没有 MEM ready 到 EX/ID 的组合直通。
MEM 只从队首消费已完成的乘法结果，并通过原 WB 寄存器顺序退休。
八项结果暂存以现有在途令牌索引，解决较老访存长时间阻塞时的结果保持。
它不允许年轻指令越过队首退休，不是独立乱序提交队列。

乘法结果提供独立的寄存广播，与原 EX/WB 广播共同按 tag 匹配。
最终加法结果先进入寄存器，不能组合直通到 ALU、分支、AGU 或 RAM 请求。
较老乘法在年轻分支误预测时继续执行；较老异常在 WB 确认时取消所有年轻乘法、结果有效位和队列项。

四项队列及寄存信用仍限制整个核心的持续接收能力；不能把单元的每拍接收能力说成所有 MUL 流都能每拍退休。
定向 SoC/核心测试观察到连续四拍接收乘法，单元测试观察到连续 259 拍接收。

## 功能与统计解释

同一性能镜像 10 次迭代退休仍为 2,808,261 条，CRC 与预测统计均保持不变。
窗口内接受 93,960 条乘法；乘法结果未取走期间，后续非乘法 EX 推进 190,800 次，
另有 17,640 次乘法接收发生在较老数据事务等待期间。
队首等待乘法结果仍有 26,640 拍，不能宣称乘法零延迟。

原 `Mul/div stall` 定义仍为 EX 队首 M 指令尚未产生可转移结果。
乘法不再占据 EX 等待，所以本镜像该计数变为零；等待部分转移到消费者的操作数等待和 MEM 队首。
因此 EX 操作数等待计数上升并不表示同样多的新增总停顿，各事件也不能相加。
新增独立测试台的 `MULTIPLY_STATS` 显示完成、队首等待和重叠情况，不增加硬件计数控制路径。
其中 completed 观察寄存广播；一般混合高/低 MUL 流可能因广播冲突而少于暂存项完成数。
本次 CoreMark 使用低位 MUL，窗口内 accepted/completed 均为 93,960。

队列为空时可能仍读出先前 MUL 载荷；本轮让该无效项不参与乘法 readiness，
避免已消费结果的 cleared-ready 位把空队列误记作 MEM 等待。
它不改变有效事务的握手、结果顺序或 CoreMark 测量周期。

## 验证覆盖

- 单元测试：四种乘法、正负与无符号边界、随机数据、结果长期保持、flush 和令牌复用。
  共接收 10,767 次，完成 10,571 次，其余被 155 次清除取消；覆盖 1,070 次低/高同拍双完成。
- 新核心定向测试：连续独立乘法、MUL 后相关、load→MUL、WAW、x0、store、分支恢复时保留较老结果。
  两组随机请求背压与 48–55 拍数据响应延迟检查乘法和访存重叠。
- 精确异常测试：较老 load access fault 在两个年轻 MUL 已启动后取消它们，
  两个目标寄存器保持原值，错误路径设备写没有发生；SoC 同步 RAM 同样通过。
- 原 14 项功能回归、47 项 ISA、BTB 模型与恢复测试、30 万拍关闭预测的取指对照继续通过。
- 原执行级 24,000 组正常对照、8,000 组故障优先级、12,000 组预测比较检查通过。
  执行级对照保留归档的旧算术单元，仅用于参考，不参与生产综合。
- 同一性能/验证镜像分别 10/1 次迭代的 CRC 和独立同窗口周期、退休、load/store/BJP 计数通过。

原固件末尾 `No BTB` 仍是固定镜像的旧文案，当前 BTB64 已启用；详见 BTB 记录。
上述短程 CoreMark 是诊断数据，未满足正式成绩运行时长。
