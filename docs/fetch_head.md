# 取指队首寄存输出实验

本页为无预测版本的历史记录。最新实现与对比见 [64 项 BTB](btb64.md)。

本轮基线为撤回入槽生产者掩码后的版本，估计 Fmax 81.900 MHz。
完整基线源码和验证记录归档于 `fetch_head/before/`。

91.166 MHz 是相同 75 MHz 约束下的布线后 STA 估计，没有修改 PLL 或上板测频。

## 结构变化

第一个候选只修改 `nc_fetch.v` 的队列输出组织，保留八项环形存储并缓存可见队首。
队首指令与 PC/故障信息共 65 位，用寄存器直接驱动 ID。
环形存储的下一项地址只由已寄存的读指针加一产生，不由 ID ready 组合选择。

- 队列有两项或更多，消费队首时从环形存储装入下一项。
- 空队列收到响应，或仅有一项且同拍出入队时，直接在时钟沿把响应写入队首寄存器。
- 停顿期间保持队首；重定向使原队列失效，过期响应沿用原协议丢弃。

队首缓存不增加队列容量，不增加固定流水拍。外部 RAM 响应没有组合直通到 ID。
取指请求、空间信用、重定向和过期请求排空逻辑保持原样。
入槽 tag 比较保持原样，也没有将组合 ready 从下游传回前端。

## 验证方法

新增 `tools/check_fetch_equivalence.py`，以归档的原版取指为参考，三个随机种子共对照 300,000 拍。
每拍检查请求握手、请求地址、输出 valid，以及有效时的指令、PC 和故障位。
覆盖空队列插入、单项同拍出入队、队首补充、指针绕回、满队列、满队列重定向、
总线背压期间重定向及过期响应丢弃。该检查已加入 `tools/run.ps1 test`。

同时重跑 14 项功能回归、47 项 ISA 测试和两组不重新构建的软件镜像：
CoreMark 性能种子 10 次迭代、验证种子 1 次迭代。
两组全部统计指标和完整 UART 输出均与本轮基线逐字节一致。

PDS 使用相同 Tcl、IP、PLL、时序约束和多角 hold 修复选项；
不通过添加 RTL 延时、放松约束或修改软件镜像制造改善。

## 第一个候选的判断

仅加队首缓存的估计 Fmax 为 80.854 MHz，LUT 5,363、FF 3,262。
slow/fast hold 为 +0.074/+0.063 ns。虽然原来的取指队列到 ID 路径已退出首要位置，
全核最差路径变为 EX 前递 tag 经分支比较到异常地址 tval，slow setup +0.965 ns。
因此不单独采纳这个候选，不能把“旧关键路径消失”当成提频成功。
证据保留在 `fetch_head/candidates/head_only/`。

## 第二个候选的变化

在队首缓存基础上，将分支 taken/untaken 和跳转的异常地址分别提前资格化。
迟到的 taken 只选择已经准备好的候选向量，异常有效位/原因仍独立产生；
避免 taken 先形成 branch_bad，再通过异常优先链资格化宽 tval。
非法指令与取指故障的 tval 优先级保持不变。

执行级对照保留原来的 24,000 组正常指令/分支向量，并新增 8,000 组故障优先级向量，
与本轮前的直接基线逐位比较完整输出包及重定向资格/目标。
新增向量包含随机坏 PC、非法指令、非法分支 funct3、取指故障、load/store 未对齐及 EBREAK。

## 当前瓶颈和边界

最差 setup 路径从 `f_tag[1]` 经逐槽前递匹配、操作数选择、移位和结果选择，
到 `memory_queue/data[1][166]`（结果 bit 17）。共 9 级逻辑，
逻辑延迟 3.884 ns、布线 6.811 ns，slow setup +2.364 ns。
另有前递到 `redirect_tag` CE 的路径 +2.408 ns，以及 RAM 返回到 WB 的路径 +2.419 ns，
三类路径接近，后续不能只缩短一个端点就假定全核继续同比提频。

本轮没有修改单发射、无 BTB、五个逻辑阶段的结构；
没有恢复已撤回的入槽生产者掩码，也没有新增等待状态、原始 RAM 到 EX 的组合旁路或跨级 ready 级联。
32 位指令存储仍映射为 32 个紫光 `GTP_RAM16X1DP`，PC/故障存储保留 FF，
避免重现之前的 FF 到 LUT RAM 写数据 hold 问题。
