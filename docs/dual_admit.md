# 双发准入、WB 转发与跨组窗口实验

2026-10-21。以已采纳的 `dual_fwd_share`（87.789 MHz）为唯一出发点，保持双 ALU、单 LSU。
**准入放宽能够提高 IPC，但这五种实现均不建议替换当前基线：同频收益最高 2.380%，不足以抵消本轮频率和资源代价。**
`accepted_dual_baseline.json`、原正式单发工程和已有采纳归档均未改动；本轮状态 RESEARCH_COMPLETE_NOT_ADOPTED，
preferred_research_candidate=dual_fwd_share。所有候选及未采用的中间实现均保留。

## 统一结果

同一份固定 10 次 CoreMark，退休指令均为 2,808,261。吞吐收益按“基线周期/候选周期”计算；
估算峰值吞吐收益再乘“候选 Fmax/87.789”，不把 IPC 提升等同于提频后的整机收益。

这些是一次完整实现的结果，不能把差异全部归因于单一 mux；局部改动也会影响其他逻辑的映射与布线。

若锁定当前约 75 MHz，组合版确实提高 2.380% 吞吐，减少 80,391 个统计周期；它并非功能无效。
但若沿用此前兼顾 IPC、频率、长链和资源的选择标准，本轮保留原版。
组合版需要至少 **85.749 MHz** 才能追平当前基线的估算峰值吞吐；其两个实现只有 81.653/82.203 MHz。

## 配对拒绝原因

仿真增加了互斥、可核对的发射组分类，未增加 CPU 硬件计数器。统计范围是已发射组，不是所有周期；
组数随配对变化，各原因也不能直接相加为可以节省的时钟数。

基线 2,684,584 个已发射组：

| 原因 | 数量 |
|---|---:|
| 没有可见第二条指令 | 1,397,635 |
| 主槽类型/故障不准入 | 128,973 |
| 第二条不是合法普通 ALU | 583,920 |
| 预测限制 | 0 |
| 同组 RAW | 130,853 |
| 同组 WAW | 0 |
| 其他 live 生产者依赖 | 250,784 |
| 成功配对 | 192,419 |

上述八项严格等于总发射组数。原统计中的 dependency_blocked=298,727 是有重叠的宽条件，
与此处按顺序分类后的 250,784 不同，不能混用。
预测限制为零仅表示经过前面类型分类后没有剩余拒绝项，不表示预测没有代价；分支预测错误仍为 61,993 次。
基线中通过其他静态条件、仅需要本拍已寄存 WB 值即可准入的组有 **24,156** 个。

跨组组合版把“没有第二条”降到 425,866，配对发射达到 314,902，其中跨组 141,167。
但跨组配对不是全部新增收益：它也改变后续同组组合，副槽退休只增加 116,122。
同组 RAW、第二条指令类型及尚未就绪的生产者仍阻挡许多组合。
更积极打包还使主槽操作数等待从 588,971 增至 624,702 拍：副槽不能绕过同组尚未准备好的主槽执行，
组的等待和访存/乘法重叠会改变，所以总周期只减少 80,391。
这说明增加准入有效，但不能用新配对数量直接估算 IPC，也不能据此认定需要双 LSU。

## 实现与控制边界

**副槽 WB 转发**：只从 `wb_q`、`wb_side_q`、`wb_v` 这些已寄存的输出取得值和有效信息，
在原 ID/EX sidecar 边界捕获。仅排除本拍确实提交的对应 lane 生产者；其他 matching live writer
仍阻挡准入，包括更年轻的 WAW。保持 WB1 优先于 WB0、x0 不转发，以及同组 RAW/WAW 拒绝。
没有副槽等待队列、没有当前 EX 结果到 ID 或 EX0 到 EX1 的组合旁路。

**peek 跨组**：用额外寄存器缓存 FIFO 的下一完整取指组。指令 RAM 读口从原“给队首装载”移动为“给下一组缓存装载”，
头部切换读取寄存的 peek；深度仍四组、最多八条指令，reserved=count+flight+cmd_valid<4 的信贷规则不变。
只拼接“干净、预测顺序执行的高半组尾指令＋下一干净双指令组的低指令”，消耗后留下该下一组的高指令。
不支持任意地址拼接，不跨故障或 taken 预测，不进行双组 pop。顺序关系由保存的取指命令/预测流保证，
并由随机前端计分板和整核仿真逐次断言检查。

**寄存窗口收尾**：进一步把 cross 有效位、第二条指令、分类位和预测一起放在头部寄存器前计算，
ID 直接读取头部寄存器，移除 ID 前 head/peek 的宽数据 mux 和 fault/count 准入门。
保留原 group_two 状态，独立于“可供配对的两指令窗口”，以正确处理消费一个或两个指令时的组归属。
前端仍有原有配对反馈到头部更新，不能声称所有 IF/ID 控制反馈均被切断。

所有方案保持原编码 tag 和比较、主槽五级执行边界、双 ALU/单 LSU、八组 ledger、ID/EX 两项、EX/MEM 四项。
EX、MEM、FIFO、寄存器文件、总线、RAM IP 和预测器 RTL 均与已采纳基线逐字节相同。
新增 WB 准入只来自 WB 寄存器；没有 MEM ready 经 EX 到 ID/IF 的新组合回传，也没有提前访存或 RAM 返回直通 EX。

## 路由长路径与资源代价

初始跨组实现仍将 fault/跨组选择、依赖判断、pair_issue 与前端头部更新串在同一周期。
初始组合版最差是 head_inst→ID 配对→IF head_inst/CE，11 级，逻辑 3.270 ns、布线 8.062 ns。
这是已有反馈依赖被新准入逻辑加重，不能描述为没有长链。
寄存窗口把窗口内容和资格提前寄存，组合版的全 head/peek 起点类最差余量从 +1.086 改善到 +1.772 ns，
但面积和其他路径代价使整核仍只有 82.203 MHz，没有追回基线。

同范围定向 STA：全部 head_*、peek_* 寄存器时钟脚，到任意时序终点，仅取 max slow corner。
另保留 WB→ID sidecar、WB→f1_valid，以及较窄指令/分类起点范围的报告；不能把较窄查询当作全部前端路径。
全部来自各自原始路由 ADIF，没有重新 PNR。

|---|---:|---:|---:|---:|
| 基线 | +1.999 | 12 | 3.728 | 6.673 |
| WB 转发 | +1.174 | 13 | 4.763 | 7.026 |
| 跨组/peek | +1.374 | 10 | 4.296 | 7.364 |
| WB＋跨组/peek | +1.086 | 11 | 3.270 | 8.062 |
| 跨组/寄存窗口 | +1.142 | 11 | 4.194 | 7.580 |
| WB＋跨组/寄存窗口 | +1.772 | 10 | 3.948 | 7.306 |

每版全局最差：

- **WB 转发**：`soc/cpu/destination1[6][2]/opit_0_inv/CLK` → `soc/cpu/operands/vb[1][4]/opit_0_L5Q_perm/L3`，12 级，逻辑 3.926 ns、布线 8.496 ns，WNS +0.330 ns。
- **跨组/peek**：`soc/cpu/fetch/head_meta[32]/opit_0_L5Q_perm/CLK` → `soc/cpu/fetch/head_meta[26]/opit_0_L5Q_perm/L4`，10 级，逻辑 4.296 ns、布线 7.364 ns，WNS +1.374 ns。
- **WB＋跨组/peek**：`soc/cpu/fetch/head_inst[4]/opit_0_L6Q_perm/CLK` → `soc/cpu/fetch/head_inst[11]/opit_0_L6Q_perm/CE`，11 级，逻辑 3.270 ns、布线 8.062 ns，WNS +1.086 ns。
- **跨组/寄存窗口**：`soc/cpu/fetch/head_inst[27]/opit_0_L5Q_perm/CLK` → `soc/cpu/operands/vb[0][15]/opit_0_L5Q_perm/L1`，11 级，逻辑 4.194 ns、布线 7.580 ns，WNS +1.142 ns。
- **WB＋跨组/寄存窗口**：`soc/cpu/multiply/forward_tag[0]/opit_0_L5Q_perm/CLK` → `soc/cpu/memory_queue/data_74/ram16x1d/WD`，12 级，逻辑 4.323 ns、布线 7.874 ns，WNS +1.168 ns。

WB 单独版的最差并非新副槽 WB 数据 mux，而是 destination1 到主槽 operands 捕获路径；其主槽表达式未改，
但共享比较/扇出、布局和布线代价仍必须计入整核评价。不能只验证新旁路自身余量充足就认定合入安全。
寄存窗口组合版最差转到乘法 forward_tag→主槽转发→EX→memory_queue，12 级；原有 WB→EX→f1_valid 链也未消失。

分布式 RAM 数量没有变化；额外 peek/窗口是有意保留的寄存状态，而非增加可用指令容量。
WB 新增的数据选择和每 lane 准入判断、跨组缓存及状态选择有实际 LUT/FF 成本。
寄存窗口在保持相同功能指标时反而比 peek 版多 356/327 LUT，不能认为“多加寄存边界就必然更省逻辑或更快”。
未删除编码 tag、取消异常条件、放开同组 RAW 或通过更多 RAM 镜像换取表面 IPC。

## 验证范围与未解决项

每个物理候选通过 63 项整核回归（含 47 项 RV32UI/UM），7 项附加检查，固定 10 次性能与固定 1 次验证 CoreMark。
附加检查包括三种子前端/4R2W RF 随机试验，共 300,000 拍、2,400,000 次 RF 读比较；
覆盖命令背压、返回延迟、重定向、故障、stale drain、单/双消费、满空信贷，跨组版还逐拍检查 peek 与下一 FIFO 项一致。
另有主槽故障取消副槽、RAW/WAW/WAR、连续双退休、精确故障及退休计数大于周期和溢出的测试。
WB 版本从实际 RTL 抽取新准入/数据表达式，对 live、目的寄存器、源寄存器、WB 标识和数据的所有二态组合做局部 SAT。
这些不是整核完整顺序形式证明。

基础三个候选的 Verilator 警告类别/数量与父版一致，无锁存器、组合环、多驱动、未驱动、隐式线或端口缺失。
**两个寄存窗口候选额外有 24 条 SIDEEFFECT 和 4 条未使用输入字段警告，不能称为 lint 清洁版。**
SIDEEFFECT 出现在 frame 函数结果直接写入拼接的非阻塞赋值处；虽然已测 Icarus 随机与 Verilator CoreMark 均通过，
本轮没有消除这些新增警告，亦不建议合入这两个版本。未使用函数输入字段不直接等于实际存储冗余。

前四份性能仿真初次报告解析遇到 WSL 混合编码错误：仿真已完成，修复解码后复用原结果，JSON 有显式标记，未重跑 PNR。
寄存窗口首次编译用了 SystemVerilog 保留字 cross 作为局部变量，已改为 borrow 后重新生成并完成全部测试；初次诊断也保留。
通用旧 harness 的 scope 文案仍写 aligned，实际配置以 generation、候选 RTL 和 cross_pairs 统计为准。

目前没有五款游戏移植后的 ELF 或帧级基准，不能将上述 CoreMark 收益当作游戏帧率收益。
本轮没有实现 Flash、显示或输入外设。下一步应围绕真实游戏程序统计每帧逻辑时间与访存等待，再决定是否继续扩大准入。
当前结果不支持为这些游戏直接增加第二个 LSU 或第三个 ALU。
