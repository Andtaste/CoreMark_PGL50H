## 功能、性能与资源

CLOCK_HZ82实际SoC固定1/10次镜像CRC和独立计数核对均通过。10次统计窗口 **2,698,740拍 / 2,808,261条**，IPC **1.04058227**；与80MHz版周期完全一致。

**11013 LUT /4476 FF /709分布RAM /48 DRM /4 APM**。相比80MHz版少27 LUT；这是时钟/UART常量与综合映射变化，不是新增CPU资源优化。未引入新跨级组合控制反馈；已有旁路选择到访存/控制的路径仍是频率限制来源。

归一化诊断 **3.705484 CoreMark/MHz**；若在82MHz通过并稳定运行，对应约 **303.85**、相对80MHz吞吐+2.5%。本轮已通过STA，尚未上板。

固件仍保留75MHz打印元数据，日志的秒数和总分应按实际时钟换算；CRC PASS与短跑<10秒的Score status分开判断。未声称官方长跑成绩或板上稳定性。

## seed 与映射检查点的复现条件

重新综合可能交换寄存器文件128个等价RAM读副本的实例名，从而扰动同一seed的布局。主目录首次重新综合后的22/4结果为setup−0.977ns；这次失败的网表、映射、路由与日志完整保留在fresh_main_failed中。全25模块结构对比证明只有这些副本名发生一一置换，原语参数、连接信号和位号均等价。

独立目录从原82MHz固定映射重新执行完整布局22／路由4，准确复现setup+0.040ns与hold最小+0.117ns。随后主工程new_core.tcl默认重新编译、综合、映射，通过所有输入SHA与完整结构连线核对后装入原固定映射，再由PDS重新布局布线与最终STA，也再次得到上述全角正余量。主工程最终原始报告与固定映射在main/中。

构建入口使用hardware/pds/checkpoints/clock82_checkpoint.json和verify_clock82_checkpoint.py。源码、IP、镜像或FDC变化即拒绝装入旧检查点；编译网表的实际连接变化也拒绝。隔离项目负向测试已验证两类拒绝都不会覆盖映射。输入变化时请使用rebuild_from_rtl.tcl重新综合并重新寻找种子；PDS GUI直接重新综合也会产生新映射。完整复现本轮结果使用new_core.tcl。没有把一组seed宣传为脱离其映射输入仍可通用。

本轮CPU RTL仅顶层时钟常量变化，完整固定1/10次功能CRC与独立硬件计数一致。未增加CPU跨模块组合控制链。全角收敛属于PDS静态时序结果，尚未上板。
