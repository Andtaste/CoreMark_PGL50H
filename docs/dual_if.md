# RAM→IF 分类最长路径调整

2026-10-20 完成。**部分判定寄存版将双发候选的估算 Fmax 从 83.382 提升到 84.710 MHz（+1.59%），
周期和 IPC 完全不变。** 建议保留 `dual_if_parts` 作为后续双发研究候选；直接化简表达式版不建议采用。
用户随后明确要求“保留”，已记录为 RETAINED_RESEARCH_CANDIDATE（见 `dual_if/retention.json`）。
正式采纳版本仍为单发，未替换生产 RTL、IP、PLL、镜像或 STA。
本轮从 `dual_ram_logic` 出发，没有合入上一轮整核频率下降的总线局部使能实验。

## 统一结果

| 实现 | LUT | FF | 分布式 RAM | DRM | APM | Fmax / MHz |
|---|---:|---:|---:|---:|---:|---:|
| 原双发研究候选 | 8412 | 4061 | 705 | 48 | 4 | 83.382 |
| 等价表达式化简 dual_if_class | 8410 | 4061 | 705 | 48 | 4 | 82.775 |
| 部分判定寄存 dual_if_parts | **8524** | **4096** | **705** | **48** | **4** | **84.710** |

部分寄存版多 112 LUT、35 FF，RAM 和 APM 不变。直接化简版少 2 LUT，但 Fmax 下降 0.73%，不据此采纳。
84.710 MHz 比更早双发实验的最高 83.942 MHz 高 0.91%；这属于小幅进步。
每个候选各一次完整 PDS，没有改 seed、时钟约束或时序例外。PLL 配置仍约 75 MHz；Fmax 是 STA 估算，未生成下载文件或上板。

| 实现 | Slow setup / ns | Slow hold / ns | Fast setup / ns | Fast hold / ns |
|---|---:|---:|---:|---:|
| 原候选 | +1.340 | +0.036 | +4.743 | +0.027 |
| 表达式化简 | +1.252 | +0.162 | +4.911 | +0.111 |
| 部分判定寄存 | **+1.528** | **+0.024** | **+5.030** | **+0.021** |

所有时序角均零失败端点，但部分寄存版最小 hold 余量仅 **21 ps**，不能把它描述为保持时间余量充足。

固定 10 次 CoreMark：3,458,702 周期、2,808,261 条退休、IPC **0.8119407223**、副槽退休 185,671 条。
固定 1 次验证镜像：347,184 周期、280,944 条退休、副槽 18,840 条。
两候选的完整 metrics/predictor/multiply/dual 字典都分别与原候选相同，CRC 通过。
没有通过限制配对、降低预测能力、增加取指/访存等待换频率。

相对正式采纳单发，同频收益仍为 4.23%；按各自 Fmax×IPC 估算，部分寄存版仍低约 **1.50%**。
约需 86.000 MHz 才能持平。因此它是双发研究进展，尚不能据此替换正式单发。
CoreMark 短运行只作诊断，继承 UART 的 No BTB 尾注不代表实际预测器配置；ENABLE_BP=1。

## 两种修改

原 `classify` 在同一拍判断 opcode/funct3/funct7 合法性，先形成普通 ALU 合法标志，再合并 load/store/MUL，
形成主槽配对资格。结果经过对齐选择、FIFO/队首选择后写入 IF 标志寄存器。

表达式化简版合并 LUI/AUIPC 共同 opcode 位，分解非移位立即数、f7=0、f7=0x20 等条件，
展开主槽资格 OR，避免源码中 ALU→primary 的层叠依赖。所有五个输出标志保持精确相等。
PDS 已会优化组合表达式，源码化简没有产生有价值的资源或整核频率收益。

部分寄存版将每条指令的五位标志改为八位部分判定：

```text
bit 7   MUL 类资格
bit 6   load/store 类资格
bit 5   f7=0x20 的 ALU 资格
bit 4   f7=0 的 ALU 资格
bit 3   LUI/AUIPC 或非移位立即数 ALU 资格
bit 2:0 write_rd / use2 / use1
```

这些位仍在**原有 IF FIFO/队首寄存边界**采样。寄存后生成 `primary = |parts[7:3]`、
`plain_alu = |parts[5:3]`，每个输出只需短 OR；对外 `pair_flags` 接口仍为每条五位、两条十位。
半组消费时八位一起移位，保持标志与指令对应。

没有增加流水级或周期，没有将完整合法性判断重新搬回 ID。FIFO 深度、请求信用、停顿、跳转恢复、
BTB、寄存器文件、生产者 tag、EX/MEM 边界和总线全部保持原样。
除 `nc_fetch.v` 外，其余核心/SoC 覆盖文件逐字节相同；IF 的时序控制 always 块也与原候选逐字节相同。

## 目标路径与寄存后控制检查

从实际已路由 ADIF 额外提取两类路径，不重新布局布线：

1. 两块 RAM 的 A 口时钟起点 → IF 分类 FIFO/队首寄存器。
2. IF 队首分类寄存器 → 所有后续时序终点，包括 ID 配对后返回 IF 的路径。

| RAM→IF 类最差者 | 逻辑级 | 逻辑 / ns | 布线 / ns | setup WNS / ns |
|---|---:|---:|---:|---:|
| 原候选 | 9 | 4.401 | 7.267 | +1.340 |
| 表达式化简 | 8 | 5.186 | 6.036 | +1.846 |
| 部分判定寄存 | 8 | 4.755 | 6.209 | **+1.821** |

部分寄存版此类路径余量改善 **0.481 ns**，退出整核最差路径。
需要如实区分：逻辑级数减少，但本次单元逻辑延迟并未下降，收益包含实际布线改善。
原版和候选取各自同类最差路径，物理 RAM 切片、寄存器位和集成 LUT/FF 端点可不同。

| 队首标志→消费者类最差者 | 逻辑级 | 逻辑 / ns | 布线 / ns | setup WNS / ns |
|---|---:|---:|---:|---:|
| 原候选 | 7 | 2.226 | 8.034 | +2.767 |
| 表达式化简 | 8 | 2.986 | 6.998 | +3.043 |
| 部分判定寄存 | 7 | 2.370 | 5.692 | **+4.450** |

新增短 OR 没有成为更差的时序瓶颈。**既有的“标志→ID 依赖/配对判断→IF 队首”跨模块反馈仍存在**，
不能说核心没有跨模块控制路径。部分寄存版该类最差路径从 `head_parts[8]` 出发，经副槽依赖与
`pair_candidate`，到 `head_inst[18]` 的 CE，余量 +4.450 ns。
PDS 可以从 RTL 的数据选择中提取寄存器 CE；源文件中关于“配对只选择 D”的继承注释描述设计意图，
不能当作物理映射保证。实际审计以 STA 为准。
没有出现新增的 MEM ready→EX→ID→IF 多级组合回传，也没有引入 EX 直驱 RAM 或 RAM 返回直通 EX。

部分寄存版新的整核最差路径为：

```text
operands/dep_b[0][1] 寄存器
  → 转发选择与 EX 计算
  → EX/MEM FIFO 写数据 data_80
```

12 级，逻辑 4.386 ns、布线 7.433 ns、setup WNS +1.528 ns；这是原有 EX 单级数据通路，相关 RTL 未修改。
后续若继续提频，应先看这条实际瓶颈，不能继续堆 IF 局部改写而假设整核频率会同步提高。

## 功能、等价与冗余检查

两候选分别通过：

- Yosys SAT：全部二进制 32 位指令的五个分类输出逐位等价，不只比较 CoreMark 出现的指令。
- 与完整译码器的 131,072 组 opcode/funct3/funct7 对照，检查主槽/ALU 资格和相应的写回、源操作数使用标志。
- 双前端 100,000 拍、200,000 次边沿前后对照，覆盖 37,701 次消费、12,228 次双消费、1,601 次重定向、778 次高半字起始重定向、566 次错误指令消费。
  输入包含任意响应数据和控制（也包含非协议的多余响应）；真实协议另由既有 IF 单元和 SoC 测试覆盖。
- 63 项整核继承回归（含 47 项 RV32UI/UM）、5 项双发附加检查，覆盖异常撤销、RAW/WAW/WAR、连续双退休；两份 CoreMark 镜像。
- Verilator lint 无锁存器、组合环、多驱动、未驱动、隐式网线和端口缺失；其余警告数量与原候选相同。

部分判定寄存并非单纯去冗余：它用更宽的 FF 状态保存未合并的谓词，以换取边界前后的逻辑平衡，
其资源代价已列入表格。声明的分类存储从 4×10+10 位变为 4×16+16 位，多 30 位；
最终 FF 多 35 个，包含综合/映射合并差异，不能把最终差额机械等同于声明位数。
分布式 RAM 和专用 RAM 均未增加。IP 源码/初始化配置与原候选相同，沿用此前真实紫光原语读回验证，
本轮没有宣称重新执行了一遍 IP 初始化测试。

完整证据见 [dual_if/comparison.json](dual_if/comparison.json)，包括源文件、测试日志、PDS、两类定向 STA、
三版原始路由 ADIF 压缩包和 SHA256 manifest。复核入口：`tools/archive_dual_if.py --preferred dual_if_parts`。
此前 RAM 优化归档 840 个文件、总线实验归档 568 个文件同时复核；正式基线 23 项源文件/IP/约束/镜像 hash 保持不变。

## 保留后的分布式 RAM 资源核查

从本版实际路由网表逐个统计，并与 PNR 分模块资源表交叉核对，最终 705 个资源单元可以精确拆分：

| 来源 | 最终分布式 RAM 单元 | 原因 |
|---|---:|---|
| 4R2W 寄存器文件 | 256 | 两个写入银行，每个为四个异步读口复制；不是架构寄存器数量变成八倍 |
| EX/MEM FIFO | 211 | 四项、宽数据包，浅而宽；最终映射已经合并/删除部分位 |
| 64 项 BTB | 174 | 两个互斥 32 项银行的 tag、target、方向/历史状态及所需读端口 |
| 取指指令 FIFO | 64 | 四项、每项 64 位；元数据/分类状态主要使用 FF |
| 合计 | **705** | 与最终 device map、PNR 总数相同 |

此前综合 RAM 表中的组件计数不能直接相加冒充最终值；本次使用最终 PNR 层次表和实际网表补齐精确拆分。
本版 IF 部分判定寄存增加的是 FF，分布式 RAM 从上一轮起一直为 705。
本机 PDS 的可用分布式 RAM 资源计数为 17,000，705/17,000≈4.15%，报告按整数显示 5%；
这不是 705 个 BRAM，也不是 705 字节。DRM 独立为 48/134≈35.82%，报告显示 36%。

Logos 架构中的分布式 RAM 位于支持存储功能的 CLMS 逻辑模块，DRM 是独立的专用块 RAM。
因此分布式 RAM 不直接扣除 DRM 块数，但会占用逻辑区的可放置资源，与其他逻辑共同使用布线网络。
PDS 分栏统计 LUT 和 Distributed RAM，不能简单用 8524+705 当作真实 LUT 占用。
架构依据：[厂商 Logos 数据手册，1.3.1/1.3.2](https://www.pangomicro.com/en/uploads/43087615_1711095655.pdf)。

对本核的影响主要是局部的：宽 FIFO 读指针驱动大量分布式 RAM 读地址，先前测得扇出 212/213；
多端口寄存器文件还有银行选择及四组读数据布线。当前瓶颈含异步 RAM 读取/选择和 EX 的组合路径，
不能因为全芯片分布式 RAM 资源单元只占约 5% 就认为没有时序代价，也不能仅凭数量认定已经拥塞。
分布式 RAM 可以放近消费者，异步读取也可能省一拍；是否优于其他实现须看实际路径与布局。

直接换 BRAM 不是无代价替换：当前小 RAM 依赖异步读，而本工程紫光 DRM IP 使用时钟读出；
四读两写寄存器文件还超过普通双口 RAM 的端口数，需要复制、分银行或修改时序。
四项宽 FIFO 若硬换 BRAM，会产生容量碎片、端口/位宽拼接与读延迟问题；
改成 FF 则增加存储 FF、读多路选择和地址/写使能布线，不能把分布式 RAM 数字降低当作整体优化成功。
本次只作核查，未改 RTL 或重新运行 PNR。

原始证据和可重复核查脚本见 `dual_if/resource_audit/result.json`、`dual_if/resource_audit/top.prr`、
`tools/audit_dual_if_resources.py`。
