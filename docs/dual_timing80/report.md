# 双发核心80 MHz时序优化

2026-10-21。上一轮 `dual_boundary_launch` 已按本次用户指令采纳；本轮为其上的隔离时序试验，尚未自动替换采纳描述。原单发工程、历史归档和固定镜像均保留。

推荐 `dual_boundary_slots`：80 MHz（12.500 ns）真实生成时钟约束下多角setup/hold全部通过，估算Fmax 80.354 MHz。固定10次窗口仍为2,807,614拍、退休2,808,261条、IPC **1.000230**，全部CRC/独立统计一致；未增加等待拍。

推荐版相对已采纳版：LUT -493、FF -20；分布RAM/DRM/APM不变。原片上50 MHz输入仍是20.000 ns，未改板级输入约束；独立复制并由紫光IP工具生成PLL，50/5×64/8=80 MHz。没有false/multicycle path、降uncertainty或换seed。

首先将副槽不可能使用的JAL/JALR控制置零；该副槽仍支持原有ALU、条件分支及共享乘法，主槽JAL/JALR不变。删掉了副槽旁路操作数经过间接地址加法、目标比较再到分支控制的无效组合路径。两位不再使用的控制在双槽ID/EX存储中被综合裁掉，副槽裁剪初版因此比launch少4个FF；空槽重构后的最终资源以表中实报为准。

另外试过将主槽导致副槽取消的条件改为更窄的配对专用判定。SAT证明等价，但完整物理结果77.083 MHz、slow setup −0.473 ns，5个违例；最差路径转移到f_valid→操作数选择→副槽结果→MEM，主要是9.408 ns布线。这项不因逻辑更少而强行保留，推荐源码没有采用它。

80 MHz物理顶层通过CLOCK_HZ参数传到UART，实际DIV=694；实RTL仿真逐拍验证0xA5完整8N1帧。测试PLL使用时钟替身，实际PLL12.500 ns周期另由PDS生成时钟报告确认。比较用SoC默认仍为75 MHz，以完整保留原镜像及测试口径。

UART80直接整合版只差0.084 ns，但仍有2个setup违例，未当作达标。其最差路径为完整非法指令译码→issue→操作数FF的CE，CE setup要求0.747 ns，布线8.831 ns。后续空槽预写版将未占用物理槽的数据及元数据按寄存的count/rd提前采样；入槽动作只在实际push时更新占用数、写指针及新指令的等待状态；pop和旁路捕获规则不变。空槽的token/dep等无效元数据也允许提前采样，在push前不会作为有效指令使用。已占用槽仍只按原旁路规则捕获值。由此移除晚到issue对宽数据/元数据CE的控制，未放宽非法指令串行化、异常精确性或配对规则。

空槽采样增加无效数据的切换活动；没有新增流水级、队列深度或有效指令等待拍，未测功耗。先做仅操作数预写的功能预检，再扩展到完整空槽；完整空槽版重新完成300000拍独立队列等价检查（600000次边沿检查），并通过整核检查和固定1/10次镜像，不以旧模块hash复用替代新逻辑验证。

这次没有增加跨模块控制链，也没有把旁路再寄存一拍。原有旁路→EX→MEM数据/控制路径和EX本地load启动路径仍存在，不能说已经全部切断；80 MHz余量以表内实际数值为准。五源旁路来源和优先级、FIFO深度、双发准入及访存返回级数不变；ID/EX空槽存储写入方式已按上文重构。

验证包括63项架构/随机差分/ISA检查、7项前端和寄存器堆/双发故障统计、6项分支乘法配对、4项取消、8项真实未来tag协议、4项乘法tag协议、4项逐拍load检查、4项MEM协议、10项地址发布检查和危险lint/SAT准入检查。副槽裁剪初版复用精确hash对应的操作数证据；空槽预写版重新执行3×100000拍独立等价检查，整核、1/10镜像、实顶层UART均另行通过。每份物理候选只跑一次PDS。

完整机器数据见 `dual_timing80/comparison.json`；RTL、工具、仿真证据、STA、失败试验和压缩路由快照见同目录清单。编译obj缓存已单独记录清理，RTL/镜像/日志/报告保留。

尚未上板。固定镜像中的75 MHz打印参数未改，因此打印的秒数不是80 MHz实测；本轮使用独立周期计数计算IPC。80 MHz相对75 MHz的同IPC理论吞吐提升6.667%，不能当成已测量的板上成绩。
