# 时序收尾与顺序双发配对评估

本版已由用户采纳，采纳记录与源码哈希见 `accepted_baseline.json`。

本轮以 86.520 MHz 的单发优化版为基线，源码和验证证据保存在 `timing_pair/before/`。
最终只有生产文件 `nc_memory.v` 改动；没有实现双发，没有改变取指、RF、BTB、乘法、
访存请求协议、EX/MEM 信用或顺序退休。用户已采纳的 BTB 记录保持不变。

## 时序收尾结果

| 指标 | 本轮前 | 本轮最终 |
|---|---:|---:|
| 估计 Fmax / MHz | 86.520 | 88.960（+2.8202%） |
| Slow setup / ns | +1.775 | +2.092 |
| Slow hold / ns | +0.068 | +0.172 |
| Fast setup / ns | +5.009 | +5.460 |
| Fast hold / ns | +0.057 | +0.124 |
| LUT | 6,412 | 6,427（+15） |
| FF | 3,444 | 3,453（+9） |
| Distributed RAM | 433 | 433 |
| DRM / APM | 48 / 4 | 48 / 4 |

改动把 byte/half/word、lane 和 signed 控制在 MEM 接受请求的同一沿预译码并寄存，
数据返回时用并行 lane 选择与符号扩展形成结果，减少返回数据经过的格式选择。
新增的 9 个寄存位都是当前 MEM 内部控制；没有插入数据流水级或增加 load 周期。
响应和下一请求同拍周转时，旧控制供 WB 捕获旧响应，新控制随新 held 上下文接手。
非法/未对齐访问仍在 EX 产生异常，访存、WB 和 redirect 边界均保留。

同一镜像 CoreMark 的全部 UART 指标与上一版逐项相同：统计窗口 3,790,552 拍、
计时 3,790,512 拍、退休 2,808,261，IPC 0.740858、诊断 CoreMark/MHz 2.638166。
全部预测统计及乘法统计也保持一致，实际 PLL 仍约 75 MHz。
因此本轮改善的是估计频率，75 MHz 下运行周期不变。没有生成 bitstream 或上板。

最差路径已转为 EX 注册转发 tag → 操作数/结果选择 → EX/MEM 写数据口：
12 级逻辑，逻辑 4.264 ns、布线 6.991 ns，setup +2.092 ns。
ID 捕获路径紧随其后，最差 +2.116 ns；原数据 DRM 返回路径未进入本次列出的最差 30 条普通 slow setup 路径。
这些仍是单级组合路径，分别在 EX/MEM 或 ID/EX 终止；新格式控制没有连通 EX→RAM 或 RAM→EX。
本轮到此收尾，后续进入双发设计时应特别保护 EX 选择与 ID 捕获两组接近的路径。

验证包括原 14 项功能回归、47 项 ISA、乘法重叠/取消、BTB/恢复/自修改代码、
30 万拍无预测取指对照、44,000 组执行比较，以及两组 CoreMark 的 CRC/独立计数。
MEM 定向测试由 Icarus、Verilator 各执行 128 轮故障/背压测试，另有 16 个连续 load，
每次周转切换宽度、符号和字节位置，并由独立 WB 寄存器确认旧响应没有使用新控制。
各模拟器共接受/响应 208 个请求，覆盖 47 次响应同拍周转，均通过。

## 配对模型及口径

`tools/assess_pairing.py` 只修改复制的仿真测试台。在同一统计窗口记录全部 2,808,261 条退休指令的
PC、原始指令、实际下一 PC、随令牌保存的 EX 预测错误标志和退休周期。
统计窗口、CRC 和全部 UART 指标与普通测试台逐项一致；轨迹内 67,899 次预测错误也与独立预测计数一致。

主模型是槽 0 普通 RV32IM、槽 1 普通整数 ALU（LUI/AUIPC/OP-IMM/非 M 的 OP）：

- 严格顺序扫描，相邻两条能配对就消耗两条，否则仅消耗较老一条；不能跳过或乱序挑选。
- 同对 RAW 不配对，x0 不建立依赖；不通过“槽 0 结果 → 槽 1 运算”缩短相关等待。
- 必须是连续 PC、实际下一 PC 也是 PC+4；不会把跳转目标指令当作第二槽。
- 较老指令若存在预测恢复，该候选不配对。分支仅在顺序路径且无需恢复时有机会配对。
- CSR/system/fence 序列化。主模型允许 WAR，WAW 按年轻者覆盖；本样本最终配对中 WAW 为零。
- 主模型假定双取指及足够 RF/完成/退休端口，不模拟操作数就绪、LSU/MUL 占用、错误路径执行或双发后的物理时序。

**这是结构机会评估，不是双发 CPU 仿真，下面的理想组内 IPC 不能当作实际 IPC 或 CoreMark 预测。**
分支正确性信息来自退休后观察，只用于排除本样本无法共同退休的配对；它不是提供给未来硬件的提前 oracle。

## 配对结果

| 模型 | 不重叠配对数 | 被配对指令占比 | 仅按宽度计算的理想组内 IPC |
|---|---:|---:|---:|
| 槽 0 全功能、槽 1 ALU，4R2W 预算 | 748,179 | 53.28% | 1.36318 |
| 两槽都仅配普通 ALU | 402,847 | 28.69% | 1.16748 |
| 全功能+ALU，但分支/跳转单发 | 653,939 | 46.57% | 1.30355 |
| 全功能+ALU，再禁止同对 WAW | 748,179 | 53.28% | 1.36318 |
| 全功能+ALU，仅允许 2R1W 端口预算 | 182,160 | 12.97% | 1.06937 |

主模型的 748,179 对覆盖 1,496,358 条指令，剩余 1,311,903 条单独成组，
总计 2,060,082 个理想发射组；相对逐条分组减少 26.6421%，不是总运行周期减少 26.6421%。
所有相邻边中有 1,043,767 个满足主模型结构条件，但其中有重叠，不能把它当作实际可发射对数。
源寄存器数量统计的是架构读需求，没有扣除可能来自转发的操作数。
2R1W 模型按这一静态需求限制端口，并假定同名源读取可以共享；因此只是端口预算的敏感性对照，
既不代表当前 RF 接口不改就能直接双发，也不是含旁路、写缓冲等实现的严格性能上限。

主模型配对组成：

| 组合 | 对数 |
|---|---:|
| ALU + ALU | 314,438 |
| LOAD + ALU | 164,272 |
| STORE + ALU | 78,969 |
| 顺序且无恢复的 BRANCH + ALU | 122,820 |
| MUL + ALU | 67,680 |

其中 546,390 对（73.03%）需要写两个不同的非零目的寄存器，
209,722 对（28.03%）读取超过两个不同的源寄存器。WAR 配对 165,560 对，需要保证较老指令读到更新前的值。
相同目的寄存器对在该样本中为零，不意味着可以忽略未来实现中的 WAW。
本测量窗口没有 DIV，不能据此推断除法密集程序的收益。

## 下一步建议

这组数据支持继续研究“槽 0 全功能、槽 1 ALU”的顺序双发，而无需一开始就增加第二 LSU 或第二乘法器。
优先验证双取指、4R2W RF 以及双完成/双退休的数据与时序接口，再整体接入第二执行槽。
现有 RF 为 2R1W、取指和退休均一条/拍，只增加 ALU 无法获得上表主模型对应的持续宽度。

配对资格应在寄存边界内确定，同对 RAW 拆开发射；第一槽的算术/分支结果不串到第二槽数据选择。
第二槽不满足条件时，第一槽仍需独立推进；异常和分支取消通过窄有效位与有序提交处理，
不生成跨多个级的宽 CE/ready 链。
分支单发可作为控制复杂度的对照选项；模型已量化其影响，不预先永久禁用这部分配对。

后续收益仍须以完整双发实现、相同镜像的总周期、PDS Fmax、hold 和资源共同判断。
单一 CoreMark 镜像的结构评估不能保证其他负载收益，也不能把宽度理想值替代实测。
