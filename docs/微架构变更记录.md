## 2026-10-15：RAM 本地快速通路

### 目标和基线

基线为 `b9e184f`：五级顺序单发射 RV32IM/Zicsr、逐从设备 RIB、单端口 RAM1/RAM2。
目标是在保留软件和存储器布局的前提下缩短片内 RAM 通路，并减少访存请求启动的空拍。
本次按用户要求控制改动范围；已有功能验证完成后，清理阶段仅做必要的编译和引用检查。

### 实际结构

```text
IF ────────────────┬→ RAM1 本地仲裁 → 原 RAM1 IP
                   └→ RAM2 本地仲裁 → 原 RAM2 IP
LSU → 地址分流 ────┬→ RAM1/RAM2 本地仲裁
                   └→ 共享外设总线 → Timer / UART / GPIO
JTAG SBA ────────────→ 对应 RAM 仲裁或外设总线
```

- RAM1、RAM2 独立服务；同一 RAM 上优先级为 JTAG > LSU > IF。
- 外设共用一条请求／响应通路。响应目标及主设备归属在接受请求时保存，避免地址改变后串回其他请求者。
- 每个主设备及每个本地端口最多一项未完成事务；允许旧响应完成与新请求在同周期发生。
- ready 不依赖该主设备自身的 valid，减少前端消费信号沿取指请求再反馈的依赖。
- 片内 RAM 访问在 EX 完成合法性检查、且 MEM 可以前进后申请；接受请求与 EX→MEM 前进同时发生。
  仲裁失败时保留 EX，已接受请求不会在 MEM 重发；MMIO 继续在 MEM 发出。
- MEM 仍等待真实响应，不硬编码“下一拍必须返回”。保留原 load-use 互锁、转发、异常冲刷和中断排空。

### 保留的功能与扩展边界

| 边界 | 当前保证／后续用途 |
|---|---|
| RAM 布局 | RAM1 64 KiB、RAM2 32 KiB；代码地址与初始化文件方式保留 |
| 跨 RAM 访问 | 数据接口可读写 RAM1；启动复制数据不受限制；保留 RAM2 取指 |
| 请求／响应握手 | 保留背压、字节使能、响应归属；后续可适配不同 BRAM 输出延迟或阻塞式 Cache |
| 前端 | 保留队列、PC 元数据及冲刷后丢弃旧响应，可继续扩展 FIFO/BTB |
| EX 本地请求 | `EARLY_LOCAL_REQUEST` 是局部时序参数；不再提供旧 SoC 总线拓扑分支 |
| 异常／中断 | 沿用五级内核的异常与中断处理，不以固定 RAM 延迟绕过它们 |
| 双发射 | 当前仍为单发射；双发射需增加发射／相关性／端口控制，不能仅修改一个参数 |

当前协议只有一项未完成事务，未来多项并发的 Cache 或双发射访存需扩展队列和事务标识。
本次不提前加入这些硬件。JTAG 与 CPU 的运行时共享通路保留，但未新增完整串行调试链上板验证。

清理旧代码前已完成：

- 47 个既有 RV32I/M 程序通过。最初重复运行了两个旧参数值，共 94 次；本地通路实际上不受该参数影响。

### LUTRAM 与 BRAM 的现状

现有报告 Distributed RAM 为 0，因此没有已确认的 LUTRAM 可直接替换成 BRAM。
当前 GPR 占约 992 FF；改用 BRAM 需处理双读单写端口、同步读及旁路，不能当作简单替换。
很浅的现有取指队列不适合只为减少少量寄存器就占用整块 BRAM。
后续较深 FIFO、BTB/PHT、Cache 数据阵列可以优先评估 BRAM；这些属于后续独立调整。
