# 受限双发的 RAM、冗余和组合逻辑检查

本轮完成于 2026-10-20，状态为 **RESEARCH_COMPLETE_NOT_ADOPTED**。所有改动位于
`simulation/results/load_bp_dual_ram*`，正式单发 RTL、IP、PLL、约束、固件和 STA 均未替换。
建议保留 `dual_ram_logic` 作为后续双发研究起点；它还不是正式采纳版本。

分布式 RAM 从上一轮双发的 **859 降至 705，减少 154（17.93%）**；硬块 RAM（DRM）从
96 恢复到 48。相同镜像的周期、IPC、预测结果、乘法统计及双发数量全部不变。
省资源没有自动解决双发频率问题：该候选 Fmax 83.382 MHz，仍低于正式单发的 89.638 MHz。

## 统一结果

资源均为 PDS 最终 device map 的计数。Distributed RAM 指分布式 RAM 原语数，不是字节；
DRM 指专用块 RAM。时钟仍配置约 75 MHz，表中 Fmax 是相同约束下的 STA 估算。

| 实现 | LUT | FF | 分布式 RAM | DRM | APM | Fmax / MHz |
|---|---:|---:|---:|---:|---:|---:|
| 正式采纳单发 | 6461 | 3520 | 443 | 48 | 4 | 89.638 |
| 上轮双发 predecode | 9206 | 4189 | 859 | 96 | 4 | 83.319 |
| 仅 BTB 分银行、压缩副槽（pilot） | 8859 | 4065 | 705 | 96 | 4 | 80.821 |
| 本轮 RAM + 平衡编码（建议保留） | **8412** | **4061** | **705** | **48** | **4** | **83.382** |
| 再精简副槽 ALU 译码 | 8401 | 4059 | 705 | 48 | 4 | 82.176 |

建议候选相对上一轮 predecode 少 794 LUT（8.62%）、128 FF、154 分布式 RAM、48 DRM。
83.319 → 83.382 MHz 只提高 0.076%，不能据此宣称明显提频；上一轮其他布局的最高值为
83.942 MHz。本轮每个物理候选只跑一次 PDS，没有换 seed 或放宽约束。

| 保留候选的时序角 | setup WNS / ns | hold WNS / ns | 失败端点 |
|---|---:|---:|---:|
| Slow | +1.340 | +0.036 | 0 |
| Fast | +4.743 | +0.027 | 0 |

保持时间通过，但最小余量只有 27 ps。精简 ALU 版 slow/fast hold 分别为 +0.149/+0.108 ns，
setup 为 +1.164/+4.502 ns；不能把两版最好的不同指标拼成一个结果。

固定 10 次迭代镜像：3,458,702 个统计周期，退休 2,808,261 条，IPC **0.8119407223**；
副槽退休 185,671 条。固定 1 次验证镜像：347,184 周期，退休 280,944 条，副槽 18,840 条。
两个合格候选与上一轮的完整 metrics/predictor/multiply/dual 字典分别逐项相等。
同频比正式单发快 4.23%；以各自 Fmax × IPC 粗估，保留候选仍低 3.04%，需要约 86.000 MHz 才持平。
这些短运行只作诊断；没有生成下载文件或上板验证。继承 UART 的 “No BTB” 尾注已经过时，
仿真观测的 ENABLE_BP=1 和预测器计数才是依据。

## 实际修改与冗余结论

1. **BTB 双镜像改为两个互斥银行。** 容量仍为带完整 tag 的 64 项；按 PC[2] 分成 32+32 项。
   对齐的两个取指字分别访问不同银行，训练只写所属银行。保持既有方向/历史状态、冲刷、
   非分支失效规则；没有通过缩容或少训练换资源。
2. **副槽流水包 102 → 65 bit。** 删除副槽 PC、rd 的重复存储：PC 使用已存在的主槽顺序 next-PC，
   rd 从已保存的副槽指令取出。EX/MEM FIFO 声明宽度 286 → 249，未增加 EX 加法器。
   仅在原有允许配对、主槽无异常时提交，异常测试覆盖主槽故障时撤销副槽。
3. **紫光非对称 TDP IP。** IF 使用 A64、LSU 使用 B32，代码 RAM 64 KiB、数据 RAM 32 KiB。
   每块只保留一份存储，删除为双字取指复制的整份镜像，DRM 96 → 48。容量、地址表、字节写、
   同一取指行的读写碰撞保护不变。生产 IP 不变，候选 IP 在各自研究目录。
4. **同等逻辑使用平衡编码。** 将“先编码 3 位组号，再按组号动态选择 lane”改为平衡树直接产生
   4 位 `{group,lane}` 编码。保留后续编码 tag 比较、转发和等待接口，没有采用用户此前拒绝的
   入槽 one-hot 掩码替代比较方案。另去掉与主槽同步更新的重复 f1_tag 寄存器声明及无用地址线。
5. **副槽专用 ALU 译码单独试验。** 已寄存的配对类别保证副槽只有普通 ALU，原完整译码器的
   分支、CSR、访存等输出不被使用。等价精简后只少 11 LUT、2 FF，Fmax 反降 1.206 MHz（1.45%）。
   因而不把这步加入建议候选。源码更短不等于最终物理效果更好。

剩余 RAM 主要是 4R2W 寄存器文件、EX/MEM FIFO、取指 FIFO 和 BTB，不是全由控制边界导致。
综合报告列出 8 个 32×32 寄存器文件读副本、4×240 的优化后 EX/MEM 存储、4×64 指令存储、
以及两个银行的 tag/target/方向状态。综合组件表与最终映射经过合并优化，不能直接相加冒充最终 705。
多端口寄存器文件的复制有端口用途；改成 FF 会增加多路选择、布线和 FF，不能当作免费去冗余。
把现有异步读小 RAM 强换为同步 DRM 也需要重新设计读延迟，未在本轮这样做。

Lint 检查未出现锁存器、组合环、多驱动、未驱动、隐式网线或端口缺失。
保留候选仍有 42 条 unused-signal 警告；精简 ALU 版为 37 条。包括包内未使用字段、trace 观测和 x0
数据位，不能把每个警告都认定为实际消耗资源的冗余。详细宽度/空端口警告保留在原始 lint 日志。

## 长链检查和仍存在的瓶颈

保持 `ex_fire = execute_valid && mem_credit`、操作数队列独立容量判断、EX/MEM FIFO 等寄存边界。
没有增加 MEM ready → EX → ID → IF 的组合回传，没有恢复 EX 提前直驱 RAM 或 RAM 返回直接旁路。
BTB 银行选择只在 IF 内，副槽 PC 复用已有 next-PC。

但不能说核心已经没有长组合路径。保留候选 slow setup 前 30 条中有以下代表路径：

| 路径 | 逻辑级 | 逻辑 / ns | 布线 / ns | 数据网最大扇出 |
|---|---:|---:|---:|---:|
| RAM A 输出 → IF 分类 → head_flags 寄存器 | 9 | 4.401 | 7.267 | 4 |
| MEM 队列读指针 → 请求/碰撞判断 → RAM CEA | 9 | 2.738 | 8.987 | **212** |
| 已寄存依赖 tag → 转发/EX → EX/MEM FIFO 写数据 | 14 | 3.721 | 8.216 | 57 |

第一条止于 IF 寄存器，未串入 ID/EX。第二条是现有访存请求与取指碰撞授权路径，仍跨到 bus/RAM，
高扇出和长布线值得下一轮单独处理。第三条是已有 EX 单级的数据通路。
本轮没有新增跨级控制长链；结构检查、lint 和关键路径检查都不能代替完整形式证明。

## 验证与初始化纠错

`dual_ram_logic` 和 `dual_ram_alu` 分别完成 63 项继承回归（含 47 项 RV32UI/UM）、5 项双发附加检查、
两份 CoreMark 镜像、随机延迟/异常/有序提交检查。IF/RF 随机单元检查含 30,000 次事务、240,000 次
寄存器读取；SoC 定向程序出现连续 65 拍双退休，且覆盖主槽异常撤销副槽。

专项对照：BTB 30,000 次更新，含 29,782 次双查询、50 次冲刷和 5,513 次失效；
生产者编码穷举 65,536 掩码 × 8 个 tail = 524,288 种；
真实生成的紫光 IP 使用厂商 GTP_DRM18K 仿真原语验证，代码 RAM 36,576 项、数据 RAM 24,288 项，
覆盖全初始化读回、两端口字序、随机字节写及一致性。精简副槽译码另比较 131,072 个编码输入，
其中 2,829 个满足配对 ALU 条件的组合逐项相同。这些是定向和随机验证，不宣称完整 ISA 形式认证。

首次 `dual_ram_wide` 曾直接拼接高低 32 位字生成 64 位初始化文件：行为级 CPU 测试通过，
但真实 IP 原语读回失败，首字 B=01130017，应为 10008117。因此该尝试明确标记为
**INVALIDATED_VENDOR_INITIALIZATION**，其时序/资源仅作诊断，不列为合格候选。
PDS 2022.2 的该非对称字节配置需要在初始化生成输入中交错字节；后续候选已修正并通过上述全读回。
原始 boot.hex 字节内容没有变化。没有只用行为模型的 PASS 掩盖 IP 初始化错误。

## 原双发为什么超过 1 IPC

对照原项目 Round50 证据报告，当前原项目 ifu/core/gpr/idu 源码 hash 与其记录相符。
该报告状态仍是 awaiting_user_decision，不能推断 Round50 已被采纳。

旧程序的统计窗口 282,245 周期，主槽退休 209,592、副槽 78,480：
**IPC = 0.742589 + 0.278056 = 1.020645**。
当前受限双发固定 10 次镜像则为 **0.758258 + 0.053682 = 0.811941**；
固定 1 次镜像也只有约 0.054265 的副槽贡献。主要差距是第二槽的使用率。
旧报告的 113,212 是整个仿真的副槽数量，不能拿来除以 benchmark 窗口。

| 能力 | 原双发当前源码 | 本次受限双发 |
|---|---|---|
| 连续指令配对 | 按指令组织的 FIFO，可跨取指组 | 仅同一个 8 字节对齐取指组 |
| 第二槽类别 | ALU、条件允许的本地 RAM load/store、条件分支 | 普通 ALU |
| 第二槽老依赖 | 可对已完成的 EX/MEM/WB 结果转发 | 有在途生产者就不配对 |
| 访存 | EX 提前本地请求、第二 LSU 及冲突处理 | EX/MEM 寄存后单 LSU 请求 |
| 寄存器文件 | FF + 多读口选择 | 分布式 RAM 复制形成 4R2W |

旧版不是任意双指令都能配对：第二槽 MUL 仍禁止，主槽分支配对未启用；条件分支是第二槽特例。
这些差异是当前受限实现选择，不是五级流水线或 FPGA 的硬性性能上限。
旧版零分布式 RAM 也有代价：Round50 after 为 11,322 LUT、6,096 FF、48 DRM，Fmax 74.322 MHz；
其配置 76.005 MHz 时 slow setup −0.298 ns、7 个失败端点。
before 为 75.632 MHz，slow setup −0.065 ns、3 个失败端点，不能把旧 76 MHz 当作完全通过时序的结果。
其中可见转发选择 → EX 地址加法 → 访存许可 → RAM 使能的 18 级路径。

旧版与新版固件构建、镜像、迭代数及退休指令数不同，上述只是结构和各自报告的解释，
不能当作同镜像 A/B 测得的微架构提升。

完整证据在 [dual_ram/comparison.json](dual_ram/comparison.json)，各候选保存源代码、生成 IP、
测试日志、PDS 命令和 STA，另有 SHA256 manifest。厂商原语只记录外部路径和 hash，不复制。
复核入口为 `tools/archive_dual_ram.py`；已有双发归档的 648 个文件同时复核通过。
