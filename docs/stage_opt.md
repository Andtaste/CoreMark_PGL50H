# 单级逻辑与等待优化

本页保留 86.520 MHz 基线；后续单发时序收尾与双发结构配对评估见 [最新报告](timing_pair.md)。

本轮以上一轮可重叠流水乘法为比较基线，原始源码、时序、CoreMark 和等待观察记录保存在
`stage_opt/before/`。BTB64 的用户采纳记录继续保存在 `accepted_baseline.json`，没有覆盖。
生产 RTL 最终只修改 `nc_core.v` 和 `nc_memory.v`；软件镜像、编译参数、PLL、约束、
BTB、取指 FIFO8、乘法和除法单元均未修改。

|---|---:|---:|
| CoreMark 统计窗口周期 | 3,966,014 | 3,790,552 |
| CoreMark 计时周期 | 3,965,973 | 3,790,512 |
| 同窗口退休指令 | 2,808,261 | 2,808,261 |
| IPC | 0.708081 | 0.740858 |
| CPI | 1.412267 | 1.349786 |
| 诊断 CoreMark/MHz | 2.521449 | 2.638166 |
| 估计 Fmax / MHz | 83.879 | 86.520 |
| Slow setup / ns | +1.411 | +1.775 |
| Slow hold / ns | +0.151 | +0.068 |
| Fast setup / ns | +4.974 | +5.009 |
| Fast hold / ns | +0.119 | +0.057 |
| LUT | 6,377 | 6,412（+35） |
| FF | 3,508 | 3,444（−64） |
| Distributed RAM | 529 | 433（−96） |
| DRM / APM | 48 / 4 | 48 / 4 |

周期减少 4.4241%，同频吞吐提升 4.6289%，估计 Fmax 提升 3.1486%。
若分别按两版估计 Fmax 换算，理论吞吐提升约 7.9233%；这只是周期与 STA 估计相乘，未在相应频率运行。
相对已采纳 BTB64、尚未流水乘法的 4,204,056 拍，同频吞吐累计提升约 10.9088%。
验证种子 1 次迭代窗口为 379,874 拍、退休 280,944，CRC 通过。
最终版本已完成独立重新布局，所有最终频率和资源均取最后一轮，未混用中间候选的 86.889 MHz。

分布式 RAM 减少约 18.15%，433 / 17,000 约为 2.55%。四项队列继续使用 LUT RAM，
优先通过载荷压缩解决浅宽浪费；不为进一步减少该数字接受全 FF 候选的频率、触发器和 hold 代价。

## 等待变化与剩余时序

| 事件 | 上轮 | 本轮最终 |
|---|---:|---:|
| EX 操作数等待 | 820,578 | 693,613 |
| 其中 load 相关 | 656,592 | 611,343 |
| 其中 ALU 相关 | 132,306 | 50,950 |
| 其中 MUL 相关 | 31,680 | 31,320 |
| ID blocked | 954,055 | 778,593 |
| EX/MEM 满且同拍出队、EX 无法补入 | 66,706 | 17,795 |
| IF 队列空 | 135,798 | 135,798 |
| MEM occupied | 718,759 | 538,807 |
| MEM 队首等待 MUL | 26,640 | 27,000 |
| 数据请求背压 | 0 | 0 |

各阶段事件有重叠，不能相加当作可节省的总周期。
窗口内 692,119 个数据事务不变，其中 180,312 次请求在旧响应拍成功周转。
ALU 结果等待随 MEM 更快推进到 WB 而减少，未增加结果银行或广播端口。
乘法延迟和流水结构不变，队首 MUL 等待增加 360 拍与更早抵达队首有关，不代表总执行时间增加。
MEM 等响应的 busy 拍仍为 692,119；ready 在成功周转拍可为真，因此它与 MEM occupied 不是同一口径。
最终 occupied 可核对为 692,119 − 180,312 + 27,000 = 538,807。

最差 setup 已转移为 **数据 DRM 输出 → bank/lane/格式选择 → WB 结果寄存器**：
6 级逻辑，逻辑 3.811 ns、布线 7.286 ns，裕量 +1.775 ns。
EX 操作数 tag → 计算/选择 → EX/MEM 写数据口是另一组接近的路径，
12 级逻辑，逻辑 3.930 ns、布线 7.570 ns，裕量 +1.872 ns。
到 redirect 寄存器的控制路径为 11 级逻辑、+1.930 ns；它仍在该寄存器终止。
原 ID 捕获路径未进入本次报告列出的最差 30 条普通 slow setup 数据路径，不能据此断言其他 ID 路径完全没有优化空间。

最差 fast hold 是已寄存的 BTB 训练 PC 到 tag RAM 写地址，0 级逻辑，裕量 +0.057 ns；
slow hold 为 +0.068 ns。均已通过，但仍应在以后改布局或频率时复核。
后续若继续提频，优先处理 MEM 返回局部布线和 EX 单级选择，不拆 RAM/WB 或 redirect 边界。

## 最终保留的结构

- ID 的循环生产者选择，改为并行求“全部匹配”与“tail 以下匹配”的编码结果，
  最后只选 3 位 tag；不先选 8 位候选掩码再串优先选择与编码。
  保留原 WAW 规则、编码 tag 和入槽 tag 比较，没有重新采用先前放弃的掩码入槽方案。
- EX/MEM 仍为四项，载荷从 280 位压缩到 184 位。PC、指令、下一 PC 和元数据保留；
  store 数据与普通结果共用一个字，访存地址、CSR 新值和异常 tval 按指令类别共用另一个字。
  CSR 的旧值仍在结果字中，因此没有丢失 CSR 新旧值同时存在的语义。
  压缩选择由已经寄存的指令类别、非法/取指故障位资格化，不增加“分支异常判定后再选宽地址”的串行链。
- MEM 可以在旧响应成功的同一拍接受下一项有序访存，旧上下文用于 WB，
  新上下文在该沿写入 held。总线原有响应/请求周转能力得以使用。
  授权依据已寄存队首及响应 valid/error 等元数据；本地总线的这些元数据已经寄存，原始 RAM 数据不参与请求授权。
- 旧响应出错时禁止发布下一请求，避免 WB 在下一拍确认异常之前，年轻设备写已经发生。
  新请求若遇到背压，进入空闲状态后仍保持同一个请求，未依赖下游 ready 来撤回 valid。
- load 的 byte/half 选择改为分层的半字、字节选择与符号扩展，移除全字节移位及重复格式选择。
  store 不写架构结果，其响应结果字段可使用同一 loaded 值，移除 RAM 到 WB 的额外 kind 选择。
- 空队列的残留 load/store 载荷不再参与 readiness，避免把无效载荷当成可周转的下一项，
  也避免忙 UART 等设备把空闲无效项误记为 MEM 等待。修正前中间候选的 occupied 计数偏低，
  最终采用有效项资格化后的 538,807；窗口周期不变。

EX/MEM 的输入信用仍只看寄存占用，不建立 MEM ready→EX→ID 的组合直通；
没有 EX 提前发 RAM 请求，没有原始 RAM 数据直通 EX，分支恢复继续跨 redirect 寄存器。
ID/EX 保持两项，乘法仍是四 APM 的流水实现，所有指令顺序退休。

## 没有保留的候选

| 候选 | 实验结果 | 决定 |
|---|---|---|
| 八令牌 EX 结果保留银行，只向操作数寄存器捕获 | 窗口只少 81 拍，较压缩队列版本增加 322 LUT、392 FF | 撤回 |
| 空闲 EX 保持上次广播 | CoreMark 窗口周期完全不变 | 撤回 |
| ID/EX 扩为三项 | 比两项少 13,530 拍，但估计 Fmax 从 86.889 降到 81.407 MHz，增加 162 LUT、262 FF | 撤回 |
| 四项 EX/MEM 强制 FF | RAM 从 433 降到 260，但多 692 FF，估计 Fmax 83.829 MHz，slow/fast hold 均只余 +0.009 ns | 撤回 |

结果相关等待不等于可以消除的周期。此前观察到的 132,306 拍 ALU 相关等待中，
大部分没有足够提前量让“下一拍再捕获”的保留银行产生收益；直接在 ID 串结果银行读取又会加重关键路径。
因此没有为了减少一个统计计数而保留整组结果银行，也没有继续增加全局广播端口。

完整候选分别归档在 `stage_opt/stage1`、`stage2b`、`stage3`、`stage4`、`stage5_id3`、`stage6_ff`。
最初结果保留银行候选曾被功能验证发现入槽数据优先级问题，已拒绝；修正版本通过两种仿真器后，
仍因实际周期收益不足撤回。该银行和对应槽位改写均未进入最终生产 RTL。

## 验证与复核

- 原 14 项回归、47 项 ISA，含随机 RV32IM 退休结果对照、CSR、精确异常、外设和定时器中断。
- 循环生产者选择按旧 head 顺序规范检查全部 4,088 组合法区间、匹配分布，仍比较依赖和编码 tag。
  不再检查已删除的内部 selected 掩码信号。
- 乘法随机/边界、同拍双完成、长响应重叠、分支恢复和较老故障取消年轻 MUL。
- BTB 模型与恢复、FENCE.I/自修改代码、30 万拍无预测取指对照、44,000 组执行结果/故障/预测比较。
- 新 MEM 定向测试由 Icarus 和 Verilator 分别执行 128 轮：连续请求/响应归属、所有合法 load 宽度及字节偏移、
  背压请求保持、load/store 访问故障、错误响应阻止年轻设备写、空队列残留设备载荷。
- 固定性能与验证镜像分别运行 10/1 次迭代，CRC、同窗口周期、退休、load/store/BJP 计数由独立测试台核对。
- 最终再次完成 PDS 布局布线并检查各角 setup/hold；`collect_validation.py` 拒绝过期综合输入。
  `archive_stage_opt.py` 再次核对 STA、CoreMark、功能测试和观察器输入的哈希，验证已采纳 BTB 记录未变。

原镜像末尾 `No BTB` 是固定固件旧文案，实际 BTB64 仍开启；独立预测统计与基线完全一致。
短程 CoreMark 为诊断数据，实际 PLL 仍约 75 MHz，没有生成 bitstream 或上板。
