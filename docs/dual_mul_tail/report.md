## 逐拍验证与实际收益

基线93,960次乘法全部为低32位MUL，接受到MEM消费都是3拍；其中55,800次在结果到达末级时，MEM已经等候该tag，但要再等结果表及available更新。其余乘法在末级形成结果时MEM尚未成为对应所有者。

候选增加按已寄存末级valid/tag匹配当前MEM tag的查询通路：结果可在写入结果表的同一边沿进入原WB寄存器。multail支持低/高位，mullowtail只提前低位，高位仍走结果表；四种MUL运算功能均保留。EX使用的M广播仍为原有寄存输出，没有把乘法末级组合结果直送EX，也没有改RAM返回旁路。若完成与消费同拍，available必须保持清除，避免旧结果在token复用时被误认；未消费的结果继续保存在原表，低/高位同拍完成仍可保存不同tag。

|---|---:|---:|
| MUL平均接受→消费拍数 | 3 | 2 |
| 末级同拍消费次数 | 0 | 93960 |
| MEM等乘法拍数 | 104040 | 48600 |
| MEM总阻塞拍数 | 125586 | 70146 |

不能把少掉的55,440拍MEM等待或93,960次提前消费直接当作整核节省。交接节奏改变后，原来没赶上末级的乘法也能更早到达MEM；与此同时，绝大多数缩短的MEM等待原本与其他流水工作重叠。整核真实净收益仅7,480拍，EX依赖结果仍经过原寄存广播。

## 双发效率与拒绝原因

副槽退休条数保持782,992、发射双发组824,282/总组2,087,263（39.49%）不变。主/副槽每周期有效退休率由74.88%/28.95%变为75.09%/29.03%，仅因为总周期变少；本轮没有扩大配对能力。统计窗口含投机发射，发射组数与最终退休组数不能混用。

以下拒绝原因使用明确优先顺序，互斥且合计等于所有发射组：

| 没有可用第二条 | 334,625 |
| 主槽类型限制 | 12,618 |
| 副槽类型不支持 | 524,597 |
| 分支/乘法副槽要求ALU主槽 | 197,408 |
| 其他预测限制 | 0 |
| 通过前面条件后仍有组内RAW | 193,733 |
| 通过前面条件后仍有组内WAW | 0 |
| 未分类 | 0 |

334,625次“无第二条”中，269,822次是主槽预测跳转，FIFO按当前设计不提供顺序第二条；64,803次是队列当时只有一条，占发射组约3.10%。后者还包含恢复过程，不能全部归因于稳态取指带宽，也不能把正确的预测跳转当成预测错误。没有观测到非连续链接或取指故障造成的剩余类别。

条件分支的资源/控制冲突是同组已经有一个控制流指令；访存列为主槽也使用LSU。RAW/WAW使用完整副槽译码，避免用现有仅支持ALU/分支/MUL的简化source-use标志误判load/store。四源就绪使用遍历实际live记账的最年轻生产者和真实F/F1/M/W/W1广播，属于观察模型，不是新准入逻辑。

可考虑的现有单元扩展范围较有限：访存主槽＋副槽分支，clean有19,989次，两条源都就绪4,708次；访存主槽＋副槽乘法16,200次，两条源都就绪10,440次；乘法主槽＋副槽分支在该镜像未观察到。单独的ALU主槽＋副槽load/store在无依赖、无资源冲突及现有预测过滤后分别26,744/3,992次，其中四源就绪7,174/1,432次。

上述是当前动态相邻窗口的机会数，尚未加入地址/对齐、异常、分支取消、成组退休和重配对成本，不能据此承诺相同数量的省拍。增加副槽访存支持也不等同于增加第二LSU：ALU＋load/store可复用单LSU，但成组等待及返回槽位仍要重构；主副槽都访存的254,105次资源冲突则确实需要串行或第二服务通路。

本轮不直接扩大准入。下一步更值得先细分组内RAW生产者，区分ALU→分支与load→分支，再评估局部方案；现有大多数机会并非仅靠放开类型就能获得。FIFO加深或完整双LSU仍不宜优先。

## 时序与控制链

两个候选各跑一次PDS，使用真实PLL80、12.500 ns、同一器件/约束/pnr选项；没有false/multicycle path、改uncertainty或seed搜索。没有将MEM ready反馈到EX输入信用，信用仍来自寄存队列占用。新增末级valid/tag→MEM完成→交接/RAM使能控制以及末级结果→WB选择确实存在，不宣称完全没有新增跨模块组合路径。

multail最差：`soc/cpu/f_data[5]/opit_0_L5Q_perm/CLK` → `soc/bus/ram_data/U_ipml_dpram_ram2_tdp/ADDR_LOOP[0].DATA_LOOP[3].U_GTP_DRM18K/iGopDrm_inv/CEB[0]`；13级，逻辑3.947 ns、布线8.808 ns，路径内最大数据扇出17。

## 验证与可复现性

每候选通过固定1/10次CRC、63项架构/ISA/随机差分、6项配对、4项取消、4项逐拍load、4项结构/lint/SAT准入、8项未来tag、4项乘法tag、6项真实posted-enabled SoC契约及实顶层UART80完整帧。独立乘法模型每版90,000拍，覆盖四运算、正负极值、随机查询/消费/背压/clear、token复用、同拍低/高位完成、完成即消费以及寄存广播优先级；原RTL观察版也通过同样90,000拍模型。操作数源文件完全未改，复用采纳版300,000拍等价证据，新W时序另由真实核心/SoC协议检查。

旧单发遗留监测器按组tag比较MUL与主槽WB，没有检查lane。新时序使副槽MUL与同组主槽ALU同拍出现，触发了错误比较。保留原失败及逐拍复现：lane1 MUL为0x49，与W1同为0x49，W0为0x1；本轮将旧比较限定lane0，并增加lane1 MUL/W1、F1/MUL一致性检查，再重跑全部架构检查，没有修改CPU去规避该断言。另修正适配器在历史runner改写argv后才读取参数的工具错误。

两份观察版全部原有统计与采纳版逐项相同，两候选固定1/10全部统计逐项相同；四个生成器输出均重建核对RTL/PLL/RAM哈希。当前采纳描述、单发参考及历史归档不修改，失败STA和压缩路由快照一起保留。仅清理本轮六份Verilator obj缓存1,014,124,955字节，源文件/镜像/仿真证据保留。

固定镜像仍打印75 MHz，软件IPC提示不支持IPC>1；本报告以独立统计窗口退休数/周期数计算。短CoreMark用于诊断，不是正式成绩，尚未上板。
