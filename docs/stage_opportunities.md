# 单级时序、等待与分布式 RAM 检查

本页保留优化前的诊断。后续候选验证和最终保留方案见 [实施报告](stage_opt.md)；
结果银行、三项 ID/EX 和全 FF EX/MEM 均经实验后撤回，不能把本页计数直接解释为可节省周期。

2026-10-20，检查对象为流水乘法最终版本，估计 Fmax 83.879 MHz。
本次没有改生产 RTL、约束、IP 或软件。增加 `tools/profile_waits.py`，
只在复制的仿真测试台中插入观察计数，使用原 10 次迭代镜像重新运行。
周期 3,966,014、退休 2,808,261、所有原 UART 指标和 CRC 与原结果逐项相同；
生产输入哈希也与最终 STA 归档一致。

## 分布式 RAM

最终设备报告为 529 / 17,000，约 3.11%；报告整数显示 4%。
LUT 为 6,377 / 42,800（14.90%），FF 为 3,508 / 64,200（5.46%）。
容量不紧张，不能把这个数字解释成用了 529 个块 RAM，也不能仅凭数量翻倍推断全局拥塞。

增量主要来自 EX/MEM 队列：四项、有效映射宽度 271 位，被综合为 271 个 GTP_RAM16X1DP。
这部分只用 16 深度中的 4 深度，按逻辑存储位算利用率为 25%，因此映射效率偏低。
BTB、寄存器堆、取指指令 FIFO 的 RAM 用法未改变；乘法结果暂存使用 FF。
综合原语明细与最终设备优化后的汇总口径略有不同，不将明细之和当作最终 529 的精确分摊。

值得做的顺序：

1. 审核并复用 EX/MEM 中按指令类型互斥的宽字段，减少队列载荷。
   必须保留 CSR 新旧值同时存在、访存异常地址和精确退休所需信息，不能盲目合并。
2. 对四项队列试 FF 或 FF 队首加 RAM 后备，比较布局后 Fmax、hold、LUT/FF/RAM 和同镜像周期。
   强制 FF 有望使 RAM 数量接近扩容前，但会增加 FF、选择网络和布线，不保证更快。
3. 暂不为了 RAM 数量把队列退回两项，也不为提高深度利用率而继续扩容。
   同步 DRM 不适合直接替换这种浅宽异步读队列；可能新增读延迟，且占用更大的存储块。

## 单级组合逻辑

Slow setup 前 30 条普通数据路径中，29 条到 ID 操作数槽，1 条到 EX 重定向寄存器。

| 路径 | 逻辑级数 | 逻辑 / 布线 | setup 裕量 |
|---|---:|---:|---:|
| IF 队首寄存器 → 源寄存器匹配 → 最新生产者选择 → tag 比较 → ID 操作数捕获 | 10 | 4.162 / 7.326 ns | +1.411 ns |
| 寄存转发 tag → EX 操作数选择 → 分支/预测比较 → redirect 寄存器 | 17 | 5.135 / 5.791 ns | +1.833 ns |

第一条布线占约 64%，`rs2[2]` 扇出 217，后段局部选择扇出 39。
优先考虑源寄存器比较的局部复制、生产者优先选择分组和捕获控制的局部化，
保留编码 tag 的正确 WAW 语义；不直接重上先前已放弃的入槽掩码方案。
需要综合网表和布局后的结果确认，不能只看 RTL 层数。

第二条仍有较深的单级控制计算，应在 ID 路径优化后重点复核。
它在重定向寄存器终止，不继续组合驱动 IF 请求/BTB；不能为减少恢复拍数拆掉该边界。
也不应不加分析地把 32 位优先选择替换为并行 OR；前轮此方案没有足够收益且产生 hold 问题。

## 等待拆分

以下计数跨阶段可能重叠，不能相加当作可节省总周期。

| 项目 | 拍数 | 解读 |
|---|---:|---|
| EX 等待 load 生产者 | 656,592 | 占窗口 16.56%，是最大操作数等待来源 |
| EX 等待 MUL 生产者 | 31,680 | 占窗口 0.80%，继续压乘法延迟优先级较低 |
| EX 等待 ALU 生产者 | 132,306 | 占窗口 3.34%；观察器确认这些生产者已经执行 |
| MEM 等数据响应 | 692,119 | 恰为 548,709 load + 143,410 store，每个事务一拍响应占用 |
| 数据请求被总线拒绝 | 0 | 当前测例不缺 RAM 端口带宽或请求接受能力 |
| MEM 队首等乘法结果 | 26,640 | 有限乘法延迟仍然存在 |
| EX/MEM 满且同拍出队、EX 无法入队 | 66,706 | 寄存信用产生的满队列恢复机会，不能直接当作总周期收益 |
| ID/EX 满且同拍出队、ID 无法补入 | 573,874 | 同样是局部信用事件，部分能由多一项缓冲吸收 |

ID blocked 954,055 拍中，886,133 拍归因于 ID/EX 满，67,899 拍为重定向，
其余为少量序列化；本测例没有八令牌耗尽导致的 ID 阻塞。
EX/MEM 真正占满四项有 87,194 拍，约 2.20%；这不代表退回两项只损失这些拍数，
因为两项时的满队列频率和下游重叠会改变。

ALU 结果等待来自当前脉冲式广播的可见性限制：在结果已经执行、尚未退休时，
晚进入 ID 的消费者可能错过 EX 广播，需要等 WB 广播。
观察到 275,898 次入槽至少一个 ALU 依赖结果已经执行，但当拍不在 EX/WB 广播上；
其中一部分被其他重叠工作遮蔽，真正观察到的队首 ALU 等待为上表 132,306 拍。
这值得评估保留已完成结果的局部转发机制，但新增全局广播端口或在当前 ID 关键路径串八选一结果读取会有代价。

## 后续优先级

1. 收紧 ID 依赖/捕获路径，并减少 EX/MEM 载荷；先恢复频率和改善布局密度。
2. 评估已完成 ALU 结果的持续可见性，尽量在局部寄存边界内完成，不扩大全局控制扇出。
3. 评估 MEM 的响应与下一请求周转，优先允许已确认属于普通 RAM 的下一读请求重叠。
   当前 `state` 在响应拍仍禁止下一请求，而本地总线已允许响应/请求同拍周转。
   实现必须保留返回归属和精确异常；MMIO 读写不能因投机提前产生副作用，
   尤其不能在较老 load 的错误尚未资格化时放行年轻设备写。
   已有 load 经 WB 寄存值到 EX 的转发，复制同拍 WB 数据不会再省一拍；不能据此增加无效旁路。
4. ID/EX 三项局部缓冲可作为对照实验，继续用寄存信用；不采用 `ready = !full || pop` 跨级直通。
   是否值得增加一项，需同时验证实际周期收益与新增选择网络的时序代价。
5. 分支恢复的 IF 空拍为 135,798，仍有预测改进空间；暂不靠取消恢复寄存器追求少一拍。

当前测例乘除 EX 阻塞为零，数据请求背压为零，也没有令牌耗尽等待。
这些项目不是目前优先继续投入的方向。
