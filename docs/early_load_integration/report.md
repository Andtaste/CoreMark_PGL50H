# 提前启动 load：整核接入实验

本轮已在隔离的完整 CPU 候选中接入并验证提前启动 load。**符合条件的 load-use 从两个 EX 空泡减为一个，但同频收益仅 0.389%，两个候选的 Fmax 均下降，且发现新增跨模块控制链，因此不采纳。** 生产 RTL、已采纳基准、原 STA、IP、PLL 和软件镜像均未改动。

用户已明确“不采纳”，两个候选均标记为 `REJECTED_BY_USER`，决策见 [decision.json](early_load_integration/decision.json)，原始数据见 [comparison.json](early_load_integration/comparison.json)。

## 实际接入的结构

ID 在基址没有活跃生产者时，用原始 RF 值和立即数计算地址，终止于 ID/EX 寄存边界。load 不使用的 CSR 旧值字段用于保存这个地址，保留原基址操作数，因此没有增加一个地址数组。额外资格状态为两个槽位各一位。

提前路径只接受合法、对齐且位于现有 RAM 范围内的 load。EX/MEM 队列必须为空；MEM 必须空闲，或能够安全完成旧的无异常操作并接受下一请求。旧异常、序列化操作、MMIO、不对齐地址、基址依赖和旧队列项均阻止提前启动。否则沿原 EX/MEM 队列路径执行。

提前请求接受与 EX 前进在同一沿发生。请求背压时保持 ID/EX 头项和已发布请求；提前 load 不再重复入 EX/MEM 队列。返回数据仍经生产 MEM 的格式化逻辑进入 WB 寄存器，然后转发到 EX。保留现有 Pango TDP RAM、总线响应和跨端口读写碰撞保护。

两个候选的区别：

- `early_load`：地址已寄存，范围与对齐资格在读出 ID/EX 头项后判断。
- `early_load_predecode`：将范围与对齐资格也在 ID/EX 边界寄存，减少地址对提前请求选择的组合控制。

两个候选的执行结果和测量周期相同。候选源码、测试平台与各自 STA 均分别归档，没有用一个版本的仿真搭配另一个版本的时序。

## 逐拍结果已经在整核成立

定向程序用冷跳转让旧指令先排空，再执行目标 load，避免 NOP 流本身一直占用旧队列项。相同镜像分别运行生产核心和候选，并比较成功结束前全部退休记录。

| 操作 | 生产版 EX 空泡 | 两个候选 EX 空泡 |
|---|---:|---:|
| `lw → addi` | 2 | 1 |
| `lw → sw` 写数据相关 | 2 | 1 |
| 指针链中第一条、基址已就绪的 load | 2 | 1 |
| 指针链中第二条、依赖第一条返回值的 load | 2 | 2 |

例如候选 `lw → addi`：沿 30 同时执行 load 并接受请求；沿 31 捕获 WB；沿 32 执行消费者。原版相对关系为 EX、请求、WB、消费者依次相隔一拍。这是完整核心、生产总线和 RAM 模型中的结果。

## 固定镜像性能与资源

固定 10 次 CoreMark 的镜像 SHA256 为 `e9abfc84cbe4cf1402b4f2f17a035e5416751893dc98a261f06a914fdc2fb9ab`。没有重新编译或安装镜像。退休指令均为 2,808,261，CRC 和独立窗口计数核对均 PASS。

| 指标 | 已采纳生产版 | 提前启动 | 资格提前寄存 |
|---|---:|---:|---:|
| 测量窗口周期 | 3,605,011 | 3,591,039 | 3,591,039 |
| IPC | 0.778988 | 0.782019 | 0.782019 |
| 同频吞吐提升 | — | +0.389% | +0.389% |
| CoreMark/MHz，诊断短跑 | 2.773946 | 2.784739 | 2.784739 |
| PDS 估计 Fmax，MHz | 89.638 | 84.624 | 88.168 |
| 按各自 Fmax 估算的吞吐变化 | — | −5.226% | −1.257% |
| LUT | 6461 | 6700（+239） | 6655（+194） |
| FF | 3520 | 3522（+2） | 3522（+2） |
| Distributed RAM | 443 | 443 | 443 |
| DRM / APM | 48 / 4 | 48 / 4 | 48 / 4 |

实际 PLL 仍约 75 MHz。在固定 75 MHz 下，这个 0.389% 的收益成立；按更高目标频率评价时，当前 IPC 提升需要至少 **89.291 MHz** 才能抵消基线频率差，两个候选均未达到。没有上板测频；Fmax 是 PDS 估计。短跑分数不作为正式 CoreMark 认证成绩。

两个候选每窗口提前接受 **24,883** 条 load，占全部 548,709 条的 **4.535%**；有 276,109 条在 ID 无基址依赖，但大多数时刻仍受旧队列/访存顺序限制而退回。整体少用 13,972 周期。EX 操作数等待从 566,646 降至 552,674，ID 阻挡从 624,189 降至 610,217。MEM 等待仍为 71,640；预测错误仍为 57,520，预测器没有修改。

验证模式的固定 1 次镜像也通过，退休 280,944 条，窗口从 361,883 降至 **360,473** 周期。

## 控制链审查与最终时序

没有建立“前递选操作数→地址加法→RAM”数据链，也没有 RAM 返回直达 EX。但提前路径让 EX 前进依赖下游请求接受，**确实新增了跨模块控制链**，不能声称本轮满足了原结构的控制隔离目标。

在最终资格提前寄存版中，报告直接列出了：

`bus.derror 寄存器 → MEM can_accept → 提前请求选择 → 总线地址/ready → ex_fire → branch_event → 统计采样寄存器`

该路径 slack **+2.090 ns**，逻辑 **3.377 ns**、布线 **7.567 ns**。它结束于寄存器，但跨越了 MEM、请求总线和 EX 控制。ID/EX 与 EX/MEM 的输入信用仍只由寄存占用决定，所以这条链没有继续串入 ID 的接收信用；这并不能消除已经出现的跨模块路径。

最终资格提前寄存版最差路径是 `fetch.head_inst[0] → ID 合法性译码/依赖资格 → operands.wb[1]`，终点为槽位 B 操作数等待标志，slack **+1.991 ns**，逻辑 **3.470 ns**、布线 **7.547 ns**。该路径为已有 ID 路径，布局变化也参与了最终频率下降；不能把全部损失归因于某一条新增逻辑。普通提前版最差为 EX 依赖/前递到分支恢复，slack **+1.516 ns**。

| 最差 slack，ns | 已采纳版 | 提前启动 | 资格提前寄存 |
|---|---:|---:|---:|
| Slow setup | +2.177 | +1.516 | +1.991 |
| Slow hold | +0.149 | +0.130 | +0.168 |
| Fast setup | +5.432 | +4.943 | +5.340 |
| Fast hold | +0.108 | +0.095 | +0.123 |

四角均无失败端点，当前约 75 MHz 约束均满足。最终两个版本各使用相同选项完整实现，没有放宽约束、去掉碰撞保护、假定总线永远 ready 或通过反复换种子挑选结果。

## 正确性与归档

每个最终候选均通过：10 组变延迟 core 定向/随机差分/预测测试；7 组 SoC 随机差分、异常、FENCE.I、自修改代码和连续退休测试；47 个继承 RV32I/M ISA 镜像；整核逐拍对比；固定 CoreMark 性能和验证镜像。

变延迟测试累计覆盖 **518 次提前接受、496 个提前请求背压周期**，检查请求稳定、请求接受与 EX 前进原子性、无重复入队和无未授权 load WB。

另用两个延迟种子向一条**确实已经通过提前路径接受的有效 RAM load**注入总线错误。两次均正确以原 PC 报 load access fault，软件检查 mtval/mepc 并恢复；年轻错误 MMIO 写和年轻 RAM 读没有越过异常。还检查了普通旧 load/store 失败时，年轻 RAM 读不能到达总线。这些是功能回归，47 项 ISA 不是完整架构一致性认证。

实验中修正了两项基础设施问题：显式提前声明网络以兼容 Icarus；扩展仿真文件名缓冲以容纳隔离目录。还修正了旁路时 MEM 等待 CSR 的绑定：队列为空时无需禁止 pop 的 ready，原绑定会多计每个提前请求的一拍。最终版本已修正，并独立核对 MEM 计数；全部最终仿真、测试和 PDS 均对应修正后的源码。初始和统计修正前记录保存在归档子目录，仅作为过程证据，不用于上面的最终对比。

源码、来源哈希、固定镜像、日志、逐拍记录、PDS 输入及报告位于 [归档目录](early_load_integration/comparison.json)，文件哈希见 `manifest.json`。复现工具为 `tools/research_early_load.py`、`tools/check_early_load.py`、`tools/check_early_load_fault.py`、`tools/research_pds.py`；增加 `--predecode` 或相应 `--variant early_load_predecode` 可选择第二版本。

**本轮不替换生产核心。** 保留“可少一拍”的整核证据，但当前实现的覆盖率、资源增量和控制链代价不支持采纳。后续若继续，优先解决访存请求所有权与 EX 推进之间的寄存边界，不能直接假定 ready 为高，或继续堆判断来扩大旁路范围。
