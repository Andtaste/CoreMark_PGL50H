# EX/ID 单级路径收尾

用户已采纳上一轮 IPC 0.778988、估计 Fmax 88.889 MHz 的版本，采纳记录已更新。
本轮比较三种保持周期和寄存边界的候选，最终只保留 EX/MEM 辅助字段生成的改动。
两个转发选择候选虽然功能等价，物理时序均下降，已经撤回。本轮最终版本已由用户采纳，后续以此版为基线。

全部报告约束满足，setup/hold 失败端点为零。hold 裕量略降，但没有接近零的候选被保留。
这是小幅提频与 LUT 减少，同频运行速度不变。PLL 仍约 75 MHz，没有修改频率、生成 bitstream 或上板。
若后续采用更高 PLL 频率，需要重新验证对应时钟配置，不能把本表当作板上测频结果。

仍使用原 10 次性能镜像及 1 次验证镜像，没有重编译软件。
性能镜像 SHA256 为 `e9abfc84cbe4cf1402b4f2f17a035e5416751893dc98a261f06a914fdc2fb9ab`。
两组 CoreMark 的全部 UART 指标、预测统计和乘法统计分别与已采纳版逐项相同；验证镜像
为 361,883 拍、280,944 条退休。不是仅以 CRC 或四舍五入 IPC 判断周期没有退步。

## 保留的改动

原最差路径从操作数 tag 经转发选择，到地址低位/对齐判断，再用对齐结果选择宽异常值，
最后生成 EX/MEM 辅助字段。地址低位的迟到控制因此影响了整个辅助字。

最终由 EX 直接按已寄存的类别、illegal/fetch fault 生成辅助字段：

| 条件，按优先级 | 辅助字段 |
|---|---|
| 取指故障 | 原指令 PC |
| 非法指令 | 原始指令字 |
| 正常译码的 load/store | 地址，包括未对齐地址 |
| 正常译码的 CSR | CSR 新值 |
| 正常译码的分支/JAL/JALR | 实际下一 PC |
| EBREAK | PC |
| 其他 | 0 |

成功分支也携带实际下一 PC，但该字段没有架构副作用。MEM 仅在异常有效时把它解释成 tval，
所以正常分支的辅助字段不需要先由对齐检查清零。分支目标未对齐时，实际下一 PC 正是所需故障地址；
条件分支未跳且顺序 PC 未对齐的参考情况同样保留。JALR 的 bit0 仍按原规则清零。

异常有效位、cause、非法/取指故障优先级、原完整 EX 输出、CSR 新旧值和内存请求授权均保持原语义。
辅助字段仍在原 184 位 EX/MEM 队列内保存，没有扩大载荷或增加寄存级。
新增的 `memory_aux` 只是已有 EX 到 EX/MEM 组合边界内的一个输出，不是越级控制或新总线请求路径。
原来完整 tval 输出在测试中仍逐位比较；生产逻辑不再为压缩后的辅助字重复构造宽异常选择。

最终生产源码只修改 `nc_execute.v`、`nc_core.v`。`nc_operands.v`、ID 的依赖编码、
取指、BTB、MEM 周转、乘法、总线、IP、约束和 PDS 选项全部与已采纳版一致。

## 没有保留的候选

下面每一行均使用本候选自己的布局布线与资源报告，所有候选的 CoreMark 周期相同。

| 候选 | Fmax / MHz | LUT | FF | Slow / fast hold / ns | 决定 |
|---|---:|---:|---:|---:|---|
| 仅辅助字段生成 | 89.638 | 6,461 | 3,520 | +0.149 / +0.108 | 保留 |
| 辅助字段 + ID 共享入槽选择 | 86.941 | 6,384 | 3,520 | +0.160 / +0.114 | 撤回 |
| 辅助字段 + 先选窄匹配信号再选广播数据 | 85.690 | 6,436 | 3,520 | +0.036 / +0.027 | 撤回 |

ID 共享入槽候选保留编码 tag 比较，并以显式逐槽优先级保证新插入覆盖旧槽广播捕获，
未采用用户此前否决的一位生产者掩码。它减少了 LUT，但最差路径变为 tag 到分支恢复寄存器，
16 级逻辑，频率下降，因此撤回。

另一个候选仍在固定槽位匹配 tag，只把较窄的匹配/等待信号先按队首选择，再选择公共广播数据。
其周期行为也一致，但布线实现更差且 hold 裕量下降，未因结构看起来更简洁而保留。

两种转发候选分别通过 3 个种子、每种子 100,000 拍的逐周期旧版对照。
比较 ready/valid/occupied、有效数据、tag、控制与预测，覆盖队满、同拍出入、clear、入槽同拍转发，
以及相同 tag、不同数值的多广播优先级；后者比整核的重复值一致约束更强。
当前生产转发源码已恢复为已采纳版本，定向对照工具保留用于复现候选，没有把未采纳候选装进核心。

## 时序边界及剩余瓶颈

EX/MEM FIFO 入队信用仍只看寄存占用，不连通 MEM ready→EX→ID。
RAM 返回仍终止于 WB，EX 结果和乘法转发仍注册；分支纠正仍先进入 redirect 寄存器。
没有新增发射条件、等待周期、直接 RAM 前递、EX 提前访存或跨流水级宽 CE 链。

原“地址低位→宽故障值→辅助字段”路径已移出最差路径。当前最差为：

`操作数 B 的依赖 tag → 乘法转发匹配/操作数选择 → 加减运算 → 结果选择 → EX/MEM 数据口`

该路径为 13 级逻辑，逻辑 4.642 ns、布线 6.528 ns，slow setup +2.177 ns。
不同版本的最差路径已经换成不同端点，不能仅因级数从 10 变成 13 就判断改动变差。
后续接近的路径包括 EX/MEM 队首到 RAM 请求使能，以及 RAM 返回到 WB。
本轮没有把控制提前跨越寄存边界去缩短它们。ID 相关候选没有获得净提频收益，未保留源码变更。

## 验证与证据

- 最终恢复的源码独立重跑 PDS，频率、资源及各角裕量与保留候选一致。
- 原 14 项功能/差分回归、47 项 RV32I/M 测试通过，覆盖异常、中断、MMIO 和随机延迟。
- 原乘法、BTB/FENCE.I、30 万拍无预测取指对照、MEM 周转及双仿真器随机完成计分板通过。
- 原 24,000 组 EX 全载荷比较、8,000 组故障优先级比较、12,000 组预测比较通过。
  在相同 44,000 组输入上新增辅助字段检查：访存/CSR 有效载荷必须相同，
  所有故障的辅助值必须与独立旧 EX 模型的 tval 相同；成功分支允许携带未使用的实际下一 PC。
- 性能、验证两组 CoreMark 的 CRC 与独立计数通过，全部指标与已采纳版逐项相同。
- 最终 STA、仿真输入及源码哈希核对一致；用户采纳记录已指向本轮最终版，保留前版采纳记录用于追溯。
