# 64 项 BTB 与八项取指 FIFO

状态：用户已于 2026-10-20 明确采纳。它是后续乘法重构的已采纳基线，
对应源码哈希见 `accepted_baseline.json` 和本页验证记录。
当前工作树后续加入的乘法流水见 [独立报告](mul_pipeline.md)；本页保留已采纳 BTB 基线的数据。

本轮实现 64 项直接映射、带完整地址 tag 的 BTB，每项配 2 位饱和方向计数器。
八项取指 FIFO 和队首寄存缓存已在前一版本实现，本轮继续使用，并增加随指令保存的预测元数据。
实际 CPU 仍为约 75 MHz，单发射、顺序执行；没有新增固定等待拍。

四项 setup/hold 均零失败端点。BTB 的 tag、目标和方向信息由 PDS 映射为紫光
GTP_RAM32X1DP/SP；保留 PLL、两块双口 RAM IP 和四个 APM。
预测元数据采用 FF，避免复制此前寄存元数据直接写 LUT RAM 的 hold 风险。

BTB 初版估计 Fmax 85.056 MHz，最差路径终止于 redirect_tag 的 CE。
最终把修正令牌每拍预写，以已寄存的 branch_redirect 资格化下一拍使用；
估计 Fmax 提高到 85.616 MHz，周期和预测计数完全不变，多 9 LUT。
这两个候选都是相同工具/参数的一次实现，不把全部物理差异归因于单个 RTL 表达式。

虽然最高频率估计低于无预测基线，若仅按两个 STA 估计分别换算吞吐，BTB 版本仍约高 14.05%。
这是算术估计；当前两者实际配置都为约 75 MHz，没有修改 PLL、生成下载文件或上板测频。

## 寄存边界和当前长路径

- IF 查询只在寄存 PC 与下一 PC 寄存器之间；RAM 请求地址由 cmd_pc FF 驱动。
- hit/taken/目标字地址共 32 位，随命令、在途响应、八项 FIFO、队首和两个 ID/EX 槽保存。
- EX 在目标和顺序两侧并行比较预测结果，不能从最终 next-PC 宽选择再反向推导控制。
- 修正 PC、令牌和有效位都跨寄存器；训练 PC/目标/类型/方向也先寄存再更新 BTB。
- 正确预测的分支不清队列；错误预测保留旧请求的握手承诺，并丢弃过期响应。
- FENCE/FENCE.I 退休产生寄存的 valid 清除命令；过期非分支命中按 tag 失效。

没有新增 EX 判断当拍穿过 BTB 再到 RAM 请求的组合级联，也没有新增 ready 反向级联。
当前最差路径是已有的 MEM 地址路径：`memory_queue/data[1][140]` 经本地总线译码、
同字读写碰撞判断到 RAM2 A 端口 CE。9 级逻辑，逻辑 3.151 ns、布线 8.282 ns，
slow setup +1.653 ns。它起于 EX/MEM 寄存边界，没有从 EX 前递/AGU 当拍串进来。
所以不能宣称所有较长组合路径已经消失；布线与碰撞控制仍是后续优化方向。

训练发生在 EX 接受非异常指令时，不等到退休；更老异常可能留下预测状态，
这只改变预测效果，不能绕过后续逐条核对、异常处理和顺序退休。
直接映射表存在容量/索引冲突；本版没有历史相关预测和返回地址栈。

## 验证和证据

- 14 项功能回归、47 项 ISA 通过；原随机参考模型核对 12,126 次退休。
- BTB 独立四状态模型：20,000 次更新，包含两端饱和、弱状态跨越、tag 冲突、失效和 flush 优先级。
- 新定向程序：交替方向、循环退出、变目标 JALR、同索引不同 tag、目标为 PC+4、代码修改后 FENCE.I。
  两组随机请求背压/响应延迟及 SoC 同步 RAM 均与指令参考模型核对，共 3,264 次退休。
- 执行级原有 24,000 组向量、8,000 组异常优先级向量、12,000 组预测比较检查通过。
- ENABLE_BP=0 时原取指逐拍对照 300,000 拍通过；同 RTL 关闭预测的 CoreMark 对照通过。
- 两组 CoreMark 的 CRC、独立同窗口计数通过；所有 RTL/约束/IP/镜像哈希与当前 STA 一致。
