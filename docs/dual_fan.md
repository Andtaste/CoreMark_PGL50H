2026-10-21。针对用户保留的 `dual_if_parts`（84.710 MHz）中，EX/MEM FIFO 读写指针的
212/213 扇出做隔离实验。**两种做法功能通过，但整核 Fmax 均下降，本轮不建议采纳。**
保留原来的 84.710 MHz 双发候选；正式采纳单发和保留记录不变。

## 方法和边界

引导版仅对 FIFO 的 rd/wr 指针和 push 使用 `syn_maxfan=64`，让 ADS 对负载作复制/分配。
手工版将 249 位 FIFO 按位宽分成四组，各自保存读/写指针，通过 `syn_preserve=1` 保留指针副本；
数据仍推导为 LUT RAM，避免退回整片 FF 存储。四组使用同样的 push/pop/reset/clear。

这些属性依据本机 PDS 2022.2-SP1-Lite 的 `ADS_Synthesis_User_Guide.pdf`，5.13/5.15 节。
属性本身不作为路由成功或满足目标扇出的证明，最终以路由网表及定向 STA 中的负载为准。

占用计数保持全局、寄存的单一来源，`in_ready=count!=DEPTH`；输出 ready 仍只影响 pop 和下一拍状态。
没有引入 out_ready→in_ready 组合路径，也没有 EX→RAM 直通、RAM 返回→EX 旁路或 MEM ready→EX→ID→IF 多级回传。
除 `nc_fifo.v` 外，核心、前端、总线、IP 和发射策略与保留候选逐字节相同。

复制指针是有意付出的物理资源代价，不是增加指令容量。手工分组使跨组的等价 RAM 位不再都能共享，
最终 memory_queue 的分布式 RAM 从 211 增为 219；其他 RAM 不变。

实际路由网表确认：指针寄存器实例从原来的 4 个变为两候选各 16 个（按位计数）。
引导版的自动副本使用 `rd_1_copy` / `wr_1_copy` 名称，已纳入统计；不能仅按原始 rd/wr 名称统计而漏掉自动副本。
在已完成的定向 STA 中，引导版观测到 15/16 个驱动的负载为 **20–64**，没有对未出现的一个驱动猜测负载；
手工版全部 16 个驱动均出现，负载为 **37–64**。原四个驱动为 **212/213**。
这证明所采用的方法能降低局部指针负载，但不证明整核更快。

| 指针起点到任意时序终点的同类最差路径 | read WNS / ns | write WNS / ns |
|---|---:|---:|
| 保留候选 | +2.315 | +10.646 |
| 引导版 | +1.552 | +10.885 |
| 四组版 | +1.381 | +10.747 |

读指针起点类路径的最差余量反而下降：两候选的新最差终点都是 MEM held 寄存器的 CE，
经过 FIFO 队首读出、MEM 请求接受/捕获控制等已有组合逻辑。
路径上仍有其他公共控制网，最大数据网扇出分别达到 258/224；不能把起点扇出降低当作整条路径扇出都降低。
定向报告只读取三版各自的原始路由 ADIF，没有重新放置布线；最终解析器补充识别自动副本时重用了同一份报告，记录了旧解析器 hash。

## 为什么没有整核提频

原读指针类路径余量 +2.315 ns，原写指针类路径 +10.646 ns，而原整核最差为 EX 路径 +1.528 ns。
因此“扇出高”并不等同于“整核最紧路径”，特别是写指针有很大余量。

引导版新的整核最差路径是 `head_inst[31] → operands/va[1][24]`，12 级，逻辑 4.305 ns、
布线 7.507 ns，余量 +1.197 ns。手工版最差为 `head_inst[53] → head_inst[21]/CE`，
8 级，逻辑 2.914 ns、布线 8.693 ns，余量 +0.905 ns。

手工版报告中还出现原有 `mtimecmp → 中断/取指 next_pc` 的 21 级路径，余量 +1.005 ns。
相应 timer、核心与 IF RTL 本轮未改，不能称其为新加入的逻辑，但物理布局后它进入关键路径，必须计入评价。
原有 ID 配对反馈到 IF 的控制也仍在，不能声称本核已没有跨模块路径。

复制少量状态改变了放置、时钟负载、数据选择和布线；不能假设优化一根网线时其余路径不变。
本轮结果不支持为降低扇出数字而采用这两版，也不支持全局盲目设置很小的 fanout 上限。
后续应根据实际临界路径，选择性复制其驱动，或先减少宽包/选择网络，而不是复制所有高扇出信号。

## 功能和冗余检查

每候选：三组独立 FIFO 计分板种子（37/613/2026），合计 300,000 拍、600,000 次边沿前后检查，
与原 FIFO 和独立参考队列同时比较。覆盖满/空、连续进出、满时 pop、清空和复位；各次清空 108/89/110 次，
每种子均有约 20,000 次同时 push/pop，数据宽度为实际的 249 位、深度为实际的四项。
另有 63 项整核回归（含 47 项 RV32UI/UM）、5 项双发附加检查、两份 CoreMark。
这些是仿真验证，不宣称 FIFO 或整核完整顺序形式证明。

Verilator 无锁存器、组合环、多驱动、未驱动、隐式网线或端口缺失；其余警告与父候选相同。
重复指针的资源保留/扇出由实际网表与定向时序核查，不把源码中的副本数直接当作最终物理副本数。
